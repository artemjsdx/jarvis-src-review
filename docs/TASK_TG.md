## Facts (verified from the README of `chigwell/telegram-mcp`, Apache-2.0; re-check with curl before relying on them)
Python 3.10+, Telethon. Env: `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `TELEGRAM_SESSION_STRING` (or file session `TELEGRAM_SESSION_NAME`); multi-account: `TELEGRAM_SESSION_STRING_<LABEL>` (tools take `account=<label>`, write tools REQUIRE `account` in multi-account mode). Transport: `MCP_TRANSPORT=http` → streamable HTTP at `http://127.0.0.1:8765/mcp` (`MCP_HOST`, `MCP_PORT`); stdio default. `TELEGRAM_EXPOSED_TOOLS=all|read-only|read-only+tool,...-tool,...` (default all). Per-call ceiling `TELEGRAM_TOOL_TIMEOUT_SECONDS` (55 s). Flood waits are surfaced with the exact wait. Session generation: `session_string_generator.py` (`--qr`, `--phone`). Keep ONE long-lived server process (many parallel sessions get accounts flagged). The PyPI package named `telegram-mcp` is NOT this project (warning in the README): install from GitHub at a pinned commit.

## Deliver

Prove each step on THIS phone (it is the target environment) and paste the outputs in the report; if some dependency cannot be installed here, say exactly which and give the fallback (e.g. run the server only when needed).
2. **Login flows** (the owner enters data in the app; the app talks to a tiny local helper, never to Telegram directly):
   a. `tools/tg/login.py` (stdlib + Telethon from the venv) as a local helper service on `127.0.0.1:8766` with a one-shot bearer token: endpoints `POST /start {api_id, api_hash, phone, label}` → sends the code; `POST /code {code}`; `POST /password {password}` (2FA); `POST /qr/start` + `GET /qr/status` (QR login, the owner scans it from another device); returns `{ok, label, me:{id,name,username,phone_tail}}` and writes `TELEGRAM_SESSION_STRING_<LABEL>` into `~/tg-mcp/.env` (atomic, mode 600) then asks `run.sh` to restart the server. Handle `FloodWait`, wrong code, expired code, 2FA required, phone banned. Codes and passwords live only in memory and are never logged.
   b. **Import**: `POST /import` with a Telethon `StringSession` string, or an uploaded `.session` SQLite file, or the JSON shape used by common session exporters (`{"api_id","api_hash","session"|"string_session", "phone"?}`; accept the `tdata`-converter `.json` + `.session` pair): validate by connecting and calling `get_me`, then store as above. Document the accepted formats in `docs/TELEGRAM.md`.
   c. **App page** `ui/settings/TelegramPage.java` (entry in `SettingsScreen`, one line + help text): accounts list (label, name, @username, phone tail, status dot from `get_me`), "Добавить аккаунт" (steps: api_id/api_hash with a link text "где взять: my.telegram.org/apps", phone, code, password) and "Импортировать сессию" (paste a string or pick a file through the system picker), per-account "Права": `Чтение` / `Чтение + отправка` / `Всё` (default `Всё`, owner's choice) written as `TELEGRAM_EXPOSED_TOOLS` + a per-account confirm-before-write toggle (default OFF for the owner's own accounts, ON via a switch), "Удалить аккаунт" (also wipes the session from `.env`), "Проверить". The page also shows the server state (running/stopped, port) with Start/Stop, and talks to the helper through `rt/TgHelper.java`. Everything goes through the existing `McpServers` entry for "Telegram" (preset from `mcpc1`): enabling an account registers/updates that entry (`url=http://127.0.0.1:8765/mcp`).
