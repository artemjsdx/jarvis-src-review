## Design (verify each assumption on the phone; document results in docs/GLASS.md)
Key insight: blur only matters for *floating* elements that sit above changing content (dock, scroll-to-bottom button, dialogs/sheets/toasts/log event window). Cards inside scrolling lists sit on the static `Backdrop` gradient and need no blur.
1. **GlassHost** (a FrameLayout owned by `Shell`): children = `content` layer (screens + `Backdrop`) and `overlay` layer above it. During `dispatchDraw` the content layer is recorded into a `RenderNode` (API 29+; invalidate only when content invalidates); a second `RenderNode` applies `RenderEffect.createBlurEffect(radius, radius, CLAMP)` (API 31+) to a downscaled draw of the first (draw at 1/2..1/4 scale to cut cost). Glass elements in the overlay layer draw their own rounded-rect region of the blurred node (translate by their position in the host, clip to the shape), then tint gradient, rim light, inner shadow. One blur pass per frame for ALL glass elements.
2. **LiquidIndicator** (dock + `SegmentedGlass` for the journal filters): a rounded "drop" lens that animates between item rects with a critically-damped spring (own tiny spring integrator on `Choreographer`, no AndroidX), stretches along its velocity (squash and stretch, volume-preserving), overshoots slightly. On API 33+ it renders refraction with AGSL (`RuntimeShader` / `RenderEffect.createRuntimeShaderEffect`): SDF of the rounded rect, edge-weighted displacement of the sampled blurred backdrop (convex lens), subtle chromatic dispersion, specular rim light from top-left, inner shadow; the icon/label underneath is magnified slightly. API 31–32: blur + rim + pill without refraction. API 26–30: today's translucent gradient look (no blur), same spring motion.
3. **Quality levels** setting `ui.glass` = auto | full | reduced | off (AppearancePage entry is owned by kit1: give them the key and a `GlassLevel` enum + `GlassLevel.effective()`); `auto` measures frame times (`Choreographer`/`FrameMetrics`) for 2 s after the first glass frame and steps down (reduce blur radius/scale, drop refraction, drop blur) when p95 frame time > 14 ms. Respect `Ui.reduceMotion`. Never allocate in `onDraw`.
4. **Integration points to deliver** (small, documented in docs/GLASS.md, wired by you only inside the files you own): dock in `Shell` uses LiquidIndicator; `Dialogs`/`OverlayHost` sheets, toasts and scrims use glass surfaces over the blurred backdrop; `Glass.floating(Context, View, Gravity, margins)` helper to place a floating glass button (for C-08 scroll-to-bottom) and `SegmentedGlass` with `setItems(String[])`, `setSelected(int)`, `setListener(...)` for L-02 (the lead wires LogScreen and AgentScreen).
5. Text and icons on glass must stay readable on both themes (use `Ui.P`; measure contrast on a bright and a dark backdrop).

## UPDATE (lead, 2026-10-29): the phone is not reachable over ADB now, and there is a way to see hardware effects WITHOUT a window
Spike S0 (do it FIRST, 30-minute cap): can `RenderEffect`/AGSL be rendered **offscreen on this phone from `app_process`** (the same runtime `tools/preview.sh` uses)? Technique (public API, API 29+): `RenderNode node = new RenderNode("x"); Canvas c = node.beginRecording(w, h); view.draw(c); node.endRecording(); node.setRenderEffect(RenderEffect.createBlurEffect(...))`; then `ImageReader reader = ImageReader.newInstance(w, h, PixelFormat.RGBA_8888, 2, HardwareBuffer.USAGE_GPU_COLOR_OUTPUT | USAGE_GPU_SAMPLED_IMAGE)`; `HardwareRenderer r = new HardwareRenderer(); r.setSurface(reader.getSurface()); r.setContentRoot(node); r.createRenderRequest().setWaitForPresent(true).syncAndDraw();` then `reader.acquireNextImage()` → `Bitmap.wrapHardwareBuffer(...)` → copy to a software bitmap → PNG. Wrap it as `ui/glass/OffscreenRenderer.render(View, w, h) -> Bitmap` and make `PreviewHost.render` use it when available (fallback to the software path). If it works: previews show the real blur/refraction, you can verify the glass work visually without ADB, and `mcp2` can reuse it for the headless UI host (`ui_screenshot`). If it does not (no GPU context in `app_process`, SELinux, driver), record exactly what failed in `docs/GLASS.md`, and fall back to: pure-software simulation of the same effect in the preview only (stack blur on the backdrop bitmap + the lens math in Java) so the DESIGN can still be reviewed; the real effect then goes to `docs/DEVICE_CHECKLIST_glass1.md` as exact steps.
