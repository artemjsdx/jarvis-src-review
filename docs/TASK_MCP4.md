# TASK mcp4 — headless UI host: see and drive the app WITHOUT a visible window (M-04, S1 solved offscreen)

Read first: `docs/AGENT_BRIEF.md` (Wave 3), `docs/STATE.md`, `docs/MCP.md` (section 4 UiHost + deviations), `docs/GLASS.md` (glass1's spike result: `ui/glass/OffscreenRenderer` renders a View tree on the GPU into a Bitmap from `app_process` on this phone, with real blur/AGSL), `docs/TASK_MCP2.md` item 5. Worktree/branch: `mcp4`. Model: Haiku.

## Why
The owner uses the phone all day and ADB is off; the lead must still see the real app and click through it. The app process already exists when the owner opened it once. A second, invisible instance of the UI inside that process (a `Shell` bound to an offscreen renderer, not to a Window) lets the agent screenshot, inspect and drive every screen with the owner's data, without touching what the owner sees. The same renderer gives screenshots on the headless ART preview, so everything is testable here too.

## Deliver
1. `mcp/HeadlessUiHost.java` implementing `UiHost` (see `UiHost`, `LiveUiHost`, `UiTools`): owns a private `Shell` created with a `Host` implementation that has no Activity window: `context()` = application context themed like the activity (reuse `JarvisApp`'s theme/inflater setup; look at `PreviewKit.host()` and `app/src/debug/.../PreviewHost` for what a window-less host needs: fonts, window-manager stubs are NOT needed inside a real app process), `post`, `navigate`, `pickDocument` (returns an error toast), `hideKeyboard` (no-op), overlays work as in the real shell.
   * Size: default 1080x2340 at the device density (`ui_host_open {kind:"headless", width?, height?, density?}`), insets from `WindowInsets` of the live window when visible else 24/48 dp.
   * Frame production: `OffscreenRenderer.render(view, w, h)` on demand (screenshot) AND an idle `Choreographer` driver so animations/springs actually advance while the host is "open" (ValueAnimator needs frames: tick the view tree with `view.layout/measure` and `draw` into the renderer at ~30 fps ONLY while an `ui_*` call is in flight or for 1.5 s after the last one; otherwise sleep to save battery).
   * Touch/key injection: build `MotionEvent`s (`obtain`, DOWN/MOVE/UP with realistic timing for swipes) and `dispatchTouchEvent` on the host's root; `ui_tap {x,y|text|desc|path}`, `ui_long_press`, `ui_swipe`, `ui_type` (insert text into the focused `EditText` via `onCreateInputConnection().commitText`/`setText` + fire editor action), `ui_key` (BACK etc. through `Shell.onBack()`), `ui_wait`, `ui_tree` (existing walker: share code with `LiveUiHost`).
   * Isolation: the headless Shell uses the SAME `Jarvis` singleton (real data!) but its own screen instances; guard against side effects that would disturb the owner: the headless host must NOT start the microphone, must not navigate the live window (`Host.navigate` stays inside the headless shell), `j.navigate()` events from agent tools (`app_open`) are routed to whichever host initiated the call (default: headless when the call came from MCP). Add `ui_hosts` fields (kind, size, current screen, frames rendered, last render ms).
2. Make `ui_screenshot {host:"headless"|"live", scale, format}` work for both (live: `PixelCopy` when the window is visible, else fall back to the offscreen render of the live decor view), returning an MCP `image` content; `ui_anim_probe {selector, property, durationMs, stepMs}` samples a view property over time on the headless host and returns the series (proves animations run).
3. Scenario tests: `tests/mcp/ui_headless.json` (open host, navigate to every dock screen, screenshot each, tap a chip on Home, open the drawer on Agent, type into the terminal, run `pwd`, read the output text from `ui_tree`), runnable against the real app via `python3 tools/mcp-smoke.py --pkg app.jarvis` and against a JVM fake where meaningful.
4. A preview-run proof on this phone WITHOUT the app installed: a debug check `HeadlessUiCheck` (like `art-run` checks) that builds the Jarvis singleton the way `PreviewKit` does, opens the headless host, performs the scripted interaction above and writes PNGs to `build/headless/`; paste the key numbers (render ms per frame, memory delta) in the report and LOOK at three PNGs.
5. Update `docs/MCP.md` (HeadlessUiHost section), `Capabilities`, `docs/DEVICE_CHECKLIST_mcp4.md` (what to run through `jv.py` once the owner opened the app: `ui_host_open`, screenshots of each screen, compare with `ui_screenshot host=live` when he is looking at the phone).
