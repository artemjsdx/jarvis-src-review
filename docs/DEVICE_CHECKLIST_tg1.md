# Чек-лист tg1: живые аккаунты (делает владелец, затем ведущий агент)

Нужен телефон, ваш Telegram и ваши api_id/api_hash. Перед началом: приложение установлено и открыто хотя бы раз.

## A. Установка помощника (Termux)

1. `bash ~/jarvis/tools/tg/setup.sh`. Ожидаемо: строка `installed: telegram-mcp 2.0.1 telethon 1.45.0 mcp 1.30.0`, код выхода 0.
2. `bash ~/tg-mcp/bin/run.sh helper-start`. Ожидаемо: `helper: started (pid …, 127.0.0.1:8766)`.
3. `bash ~/tg-mcp/bin/run.sh status`. Ожидаемо: «сервер: остановлен» или «работает» (зависит от аккаунтов), «помощник входа: работает», «права файла .env: 0o600».
4. `cat ~/tg-mcp/helper.token`. Скопируйте строку.

## B. Токен в приложении

5. Настройки → «Telegram-аккаунты». В блоке «Токен помощника» вставьте токен, «Сохранить токен».
   Ожидаемо: блок показывает «Токен сохранён». Статус сервера: «остановлен» (аккаунтов ещё нет).
6. Для проверки без входа: откройте страницу ещё раз, ошибок «помощник не запущен» быть не должно.

## C. Вход одним способом (код)

7. «Добавить аккаунт». api_id, api_hash с my.telegram.org/apps, телефон в международном формате, имя аккаунта `owner`. «Код в Telegram».
   Ожидаемо: переход к полю кода, сообщение «Код отправлен».
8. Введите код из Telegram. Если включён пароль 2FA: введите его (он не сохраняется). Ожидаемо: лист закрывается, сообщение «Аккаунт «owner» подключён. Сервер перезапущен.», в списке «Иван …» с хвостом телефона и статусом «не проверен».
9. В Termux: `bash ~/tg-mcp/bin/run.sh status`. Ожидаемо: «аккаунты (1): owner», «MCP initialize: ок — telegram-mcp …», «порт 8765 открыт».
10. В приложении: нажмите аккаунт → «Проверить подключение». Ожидаемо: «Аккаунт «owner» в сети», статус «в сети».

## D. Вход по QR (второй аккаунт, по желанию)

11. «Добавить аккаунт» → «Войти по QR-коду». Отсканируйте код с другого устройства (Настройки → Устройства → Подключить устройство). Ожидаемо: код виден, после скана — аккаунт в списке. Если код устарел, ссылка обновится сама.

## E. Импорт сессии (по желанию)

12. «Импорт сессии» → вставьте строку сессии или выберите файл `.session`/`.json`, укажите api_id и api_hash. Ожидаемо: «Аккаунт импортирован». Неверная сессия → понятная ошибка, аккаунт не добавляется.

## F. Проверка агентом (только чтение)

13. Ведущий агент вызывает через MCP: `mcp_search {"server":"telegram","query":"get_me"}`, затем `mcp_call {"server":"telegram","tool":"get_me","arguments":{"account":"owner"}}`. Ожидаемо: ваше имя и @username.
14. `list_chats {"unread_only":true,"limit":10,"account":"owner"}`. Ожидаемо: список непрочитанных (или пустой список).
15. `get_history {"chat_id":"<id из шага 14>","limit":3,"account":"owner"}`. Ожидаемо: последние сообщения. Ни одно сообщение не должно отметиться прочитанным.

## G. Права и подтверждение

16. Права «Чтение»: `mcp_search {"server":"telegram","query":"send_message"}` не находит отправку (сервер её не регистрирует). Затем вернуть «Чтение и отправка».
17. Переключатель «Спрашивать перед действиями» включить. Попросите агента отправить себе «тест» (через навык telegram-reply, после «да»). Ожидаемо: диалог подтверждения в приложении. Без подтверждения сообщение не уходит. Выключить переключатель обратно.
18. Лимит: за минуту агент не может отправить больше 20 действий записи. Проверка не обязательна (тестируется в JVM-тестах `TelegramCoreTest`).

## H. Остановка и удаление

19. Кнопка «Остановить» на странице. Ожидаемо: «работает» → «остановлен», порт закрыт.
20. По желанию: «Удалить все данные Telegram». Ожидаемо: список аккаунтов пуст, в Termux `.env` без строк `TELEGRAM_SESSION_STRING`, пункт «Telegram» исчез из «Внешние MCP-серверы». В Telegram: Настройки → Устройства → завершить сеанс «Jarvis» (сессия остаётся активной, пока её не завершить).

## Что записать ведущему агенту

- Результат шагов 9, 10, 13, 14: успех или текст ошибки (без секретов).
- Версия upstream из `status` и время первого ответа MCP.
- Сбои: любая строка из `~/tg-mcp/server.log` с «Traceback» или «error».
