## Ranked problems (from docs/SPEED.md section 6) and what to build — each with a number before and after
1. **LLM 3–6 s per voice command; commands with tools need TWO sequential LLM calls** (≈ 3 s to first text after the tool result). Also 36 tool schemas ≈ 8.7K input tokens every turn.
   a. **Fast confirmations for direct commands (P-06)**: setting `direct.confirm` = fast | live | auto (default auto). `fast`: speak the template reply immediately from the TTS cache (no LLM call); `live`: current behaviour (LLM phrases the confirmation from the real tool result); `auto`: `fast` when the median LLM first-token time of the last 5 turns > 2.0 s or the network probe says weak, else `live`. Pre-synthesise the ~25 most common confirmation phrases ("Включаю музыку", "Поставил на паузу", "Готово", "Открываю файлы", …) in the user's primary TTS voice into `TtsCache` when idle (`tts.prewarm` exists: extend it, bounded by quota: ElevenLabs free quota is tiny — never prewarm through ElevenLabs automatically; use the free providers).
   b. **Quick acknowledgement (C-10)**: for voice turns that are NOT direct commands: if no LLM text has started `ack.delayMs` (default 900) after the end of speech, play one short cached phrase ("Секунду.", "Принял, смотрю.", "Сейчас гляну."; configurable list; setting `ack.mode` = off | voice | always, default voice). Never repeat the same phrase twice in a row, never play it when real text arrives first, never over the real answer (stop it cleanly if the answer arrives, or let it finish if < 300 ms left). The ack audio comes from the cache so it starts in ≈ 100–200 ms.
   c. **Prompt prefix stability (P-04)**: today `Prompts.system` mixes the stable rules with `СЕЙЧАС:` (changes every minute), player, device, memory, extra — any byte change before the history invalidates provider prefix caches (DeepSeek/OpenAI automatic caching, Anthropic `cache_control`). Restructure: [stable core + tools + memory (changes only when saved)] first; the volatile block (time, player state, device, one-off hints) is attached to the CURRENT user message for the request only (e.g. a short `[контекст: …]` line appended in `AgentRunSpec.user`), while the persisted history keeps the raw user text. Add `cache_control: {"type":"ephemeral"}` on the system message and the last stable history message when the model id starts with `anthropic/` (OpenRouter forwards it) — behind a per-provider capability flag, with a unit test that the JSON is valid for providers that ignore it. Verify with `cached_tokens` in the usage of consecutive live calls (tools/bench/llm_ttft.py-style, cheap model, ≤ 0.2 USD) and report the numbers honestly (speed1 found upstream variance dominates; say what you measured).
   d. **Tool schema diet**: measure tokens per tool (`tools/bench/schema_tokens.py`: serialise `ToolRegistry.specs()` and count with a chars/3.2 estimate and the real `prompt_tokens` delta); shorten descriptions and parameter text (keep meaning, Russian), drop redundant words; optionally group rarely used tools (adb_*, termux_exec, web_* when present, memory admin) and include a group only when the user text/last tools suggest it or the model calls the meta-tool `tools_enable(group)` — implement ONLY if tests show no loss: a table-driven test with ≥ 40 realistic Russian commands must route to the right group (or the fallback meta tool works in the loop). Report tokens before/after.
   e. **Skip the second LLM call when it adds nothing**: tools may return an optional `spoken` hint (add to `ToolResult`, additive); in `fast`/`auto-fast` mode, when ALL tool calls of a step succeeded and every result has `spoken`, finish the turn locally with the joined hints (no second LLM request). Implement for the music_*, app_open, app_setting, speech_stop, fs_mkdir/fs_write/note_create tools.
2. **TTS: synthesis of the next sentence does not start while the previous one plays (0.6–0.9 s silence per boundary)**: implement look-ahead synthesis (prefetch chunk N+1 as soon as chunk N starts playing, bounded to 1 chunk ahead; cancel/clear on stop; respects cache and provider fallback). Measure the gap with the trace (`play_gap`/inter-chunk silence) before/after on the e2e harness (`SpeedE2E`).
3. **End-of-speech silence is a fixed 650 ms**: expose `stt.endSilenceMs` (default 550), and a short adaptive rule (if the transcript-so-far is unfinished — ends with a conjunction/preposition/«и», «а», «но», comma — wait +250 ms once). Test with the segmenter on recorded audio (tests exist for `Segmenter`).
4. **Provider routing by latency (P-07 part)**: keep a rolling per-provider first-token latency (EWMA, persisted); when the primary exceeds `llm.hedgeMs` (default 4000) without a first token, fire the first fallback in parallel and take whichever delivers first, cancelling the loser (only before any side effect; never double-run tools). Unit-test with MockServer (slow primary, fast fallback; both fast; primary error).
