# TASK MEDIA — Android audio layer + pure-Java audio logic

Owner dirs: `app/src/main/java/app/jarvis/media/**` (Android classes), `app/src/main/java/app/jarvis/core/audio/**` (pure Java, JVM-testable), tests under `app/src/test/java/app/jarvis/core/audio/**`, ART checks under `app/src/debug/java/app/jarvis/dev/checks/media/**`.

**Frozen contracts:** `media/{SpeechOut,MusicOut,MicIn}.java` and the voice contracts `core/voice/{AudioSink,AudioSpec,PcmAudio}.java` (read them). You implement:

## 1. `media.SpeechPlayer implements SpeechOut` (+ helpers)
* A serial queue (single worker thread; the producer of the head utterance runs on it). For each utterance: `listener.onUtteranceStart`, create a fresh `AudioSink` implementation, call `producer.produce(sink)`, wait until the audio has really finished playing, `onUtteranceEnd(id, completed)`.
* The sink decodes by `AudioSpec`: `PCM_S16LE` (rate given) → AudioTrack directly; `WAV` → parse header on the fly (PCM16, any rate, mono/stereo; tolerate `data` size 0/0xFFFFFFFF streaming headers) → AudioTrack; `MP3` (and `AAC_ADTS`, `OGG_OPUS` if cheap) → **streaming decode with `MediaCodec`** (frame-split the byte stream first: write `Mp3FrameSplitter` that finds sync words and frame lengths from the MPEG header incl. ID3v2 skipping and tolerates arbitrary chunk boundaries and garbage; decoder rate/channels come from the codec output format; handle `INFO_OUTPUT_FORMAT_CHANGED`; stereo/mono; sample-rate up to 48 kHz). Audio must start playing **before** the stream ends (time-to-first-audio matters). Use `AudioTrack` in `MODE_STREAM`, `USAGE_ASSISTANT`/`CONTENT_TYPE_SPEECH` (fallback `USAGE_MEDIA`), a buffer of about 2× `getMinBufferSize`, and pre-buffer ~120 ms before `play()` to avoid underrun clicks. `onFirstAudio(id, ms)` is measured from `onUtteranceStart` to the first `AudioTrack.write` of non-silent data (state this definition in a comment).
* `stopAll()` must stop within ~100 ms: flush/stop the track, interrupt blocked writes, make the producer's sink calls fail fast (`write` throws `IOException("stopped")`), drain the queue.
* Loudness: compute RMS of the PCM being written, call `listener.onLevel(0..1)` about 30 times/s (smoothed), 0 at the end.
* Back-pressure: `sink.write` blocks while more than ~3 s of audio is buffered.
* `duck(true)` → volume ×0.35 (restore on false); `setVolume`.
* Request audio focus (`AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK`, `AudioFocusRequest` API 26) when speaking starts and abandon when the queue empties; if focus is denied still speak but log it through the listener's `onError` text.
* Must not leak: `release()` frees codecs, tracks, threads. Handle `MediaCodec` creation failure (no MP3 decoder) with a clear `IOException` message.

## 2. `media.MusicPlayer implements MusicOut`
* Backed by `android.media.MediaPlayer` (one instance reused or recreated per track — your choice), `AudioAttributes(USAGE_MEDIA, CONTENT_TYPE_MUSIC)`, audio focus (`AUDIOFOCUS_GAIN`; pause on `LOSS_TRANSIENT`, lower volume on `CAN_DUCK`, stop on `LOSS`; resume after `GAIN` if it was paused by focus loss), `setWakeMode(PARTIAL_WAKE_LOCK)` is **not** needed (the host service holds the wake lock).
* `play(file,title)` blocks until playing really started: `prepare()` (synchronous, on the caller thread — the caller is a tool worker thread) → `requestFocus` → `start()`; throw `IOException` with a Russian message for: missing/empty file, unreadable, unsupported format, focus denied (`"Не удалось получить аудиофокус: другое приложение использует звук"`). Track completion advances the queue; `onMusicChanged` fires on every change; `info()` returns live position/duration.
* Constructor `MusicPlayer(Context ctx)`. Also provide `media.MediaNotifications` helper: builds a `Notification` (channel creation incl.) showing title, state, and actions Play/Pause, Previous, Next, Stop via `PendingIntent.getService`/broadcast to an action string the host defines (`MediaNotifications.ACTION_*` constants; the host service handles them and calls the MusicPlayer), using `Notification.MediaStyle` + a `MediaSession` (`android.media.session`) so lock-screen/Bluetooth buttons work; expose `MediaSession` callbacks → MusicPlayer. Keep it testable: `MediaNotifications.build(Context, MusicOut.Info, ...)`.

## 3. `media.MicCapture implements MicIn`
`AudioRecord` with source `VOICE_RECOGNITION` (or `VOICE_COMMUNICATION` when `aec=true`, additionally enable `AcousticEchoCanceler`/`NoiseSuppressor` if available), 16 kHz mono PCM16, buffer ≥ 4× min, read loop on a dedicated thread (priority `THREAD_PRIORITY_URGENT_AUDIO`), frames of 20–30 ms to the listener, graceful `stop()` (join), clear `lastError()` strings in Russian ("Нет разрешения на микрофон", "Микрофон занят другим приложением" …). It has to be impossible to leave the microphone open after `stop()`.

## 4. Pure-Java `core.audio` (JVM unit-tested with real speech samples)
* `Vad`: adaptive-threshold voice-activity detection on 16 kHz frames (noise-floor tracking with slow adaptation + hysteresis; combine RMS and zero-crossing/spectral-tilt cheaply; no FFT library). Must not trigger on constant noise/hum and must follow slowly rising noise.
* `Segmenter(Config, Listener)`: feeds on frames; keeps a ring **preroll** buffer (default 450 ms) so the beginning of speech is never cut; emits `onSpeechStart`, `onLevel`, and `onUtterance(PcmAudio, startMs, endMs, truncated)` when speech ends (`endSilenceMs` default 650) or `maxUtteranceMs` (default 14 000) is reached (`truncated=true`); drops blips shorter than `minSpeechMs` (default 220); `setEnabled(false)` pauses detection (while the assistant speaks) and clears state; `reset()`.
  Test with: `$TMPDIR/svet16k.pcm` surrounded by silence and by synthetic noise (white noise at −45/−35/−30 dBFS), two utterances separated by 0.9 s of silence, one separated by 0.3 s (must stay one utterance), start-of-speech preservation (first 100 ms of the word are present in the output: compare with the source), preroll at buffer start.
* `WakeMatcher`: `WakeMatcher(List<String> phrases)` + `static WakeMatcher defaultRu()` (phrases: "джарвис", "джарвиз", "жарвис", "джервис", "джарвес", "ярвис", "джарвис,", "эй джарвис", "привет джарвис", "хей джарвис", "jarvis"). `Match match(String transcript)` → `found`, `heard` (the matched token), `command` (everything after the wake phrase, trimmed of punctuation, may be empty), `score` 0..1, `positionOk` (wake word must be at the beginning or within the first 3 words — avoid reacting to "…сказал джарвис вчера"). Normalise: lower-case, `ё→е`, strip punctuation, collapse spaces, Latin→Cyrillic homoglyph fold where unambiguous; fuzzy match with Levenshtein ≤ 1–2 (scaled by length) plus a few phonetic collapses (ж/дж, з/с at word end, безударные а/о). Unit-test with many realistic ASR outputs ("жарвис папочка проснулся", "Джарвис, включи музыку", "джервис стоп", "ну привет джарвис что там", "джарвис" alone, false positives: "гарвис", "карвис", "дарвин", "джаз", "сервис", "вис", "автосервис", text with 'джарвис' late in a long sentence).
* `core.audio.WakeFlow` is **not** your job (the lead writes it).

## ART verification (required)
Under `app/src/debug/java/app/jarvis/dev/checks/media/`:
* `DecodeCheck`: feed each sample (`$TMPDIR/edge_ru-RU-SvetlanaNeural.mp3`, `el_*.mp3`, `silero_*.wav`, `el_*.pcm` at 24 kHz) in odd-sized chunks (e.g. 777 bytes) through the **same decode path** as `SpeechPlayer` but into a counting PCM sink (so no audio device is needed), print decoded duration vs `ffprobe` duration (must agree within ~3 %), time to first PCM, and that no exception occurs. Compare RMS to detect silent output.
* `PlayCheck`: actually construct `SpeechPlayer`, play a sample through the **real AudioTrack** (the phone speaker may emit sound — fine), report `onFirstAudio`, completion, `stopAll()` latency; `MusicPlayer` on a real file (convert a sample to `$TMPDIR/music_test.mp3` with ffmpeg; MusicPlayer needs a `Context`: if the headless ActivityThread system context from `PreviewHost` is not enough, use it as far as possible and report exactly what failed, e.g. focus request or MediaSession needing a real app).
* `MicCheck`: try `MicCapture.start` and report `lastError()` (Termux may lack RECORD_AUDIO; that outcome is fine, just report it).
Run with `bash tools/art-apk.sh <class>` and report numbers.
