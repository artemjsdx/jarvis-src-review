# Контекст и промпт — ключи настроек (X-06, X-05, S-17)

Страница: Настройки → «Контекст и промпт» (`ui/settings/ContextPage.java`). Размер запроса считает `core/agent/PromptReport.java`
через `AgentRunner.promptReport(conv)`; тот же отчёт есть в MCP `agent_prompt_dump` (поле `report`).

| Ключ | По умолчанию | Диапазон | Подпись в приложении | Что меняет |
|---|---|---|---|---|
| `memory.budget` | 2000 | 200–20 000 | Бюджет памяти, символов | сколько памяти попадает в системный промпт (`MemoryStore`) |
| `llm.contextChars` | 60000 | 8 000–400 000 | Лимит истории, символов | окно контекста: старые сообщения обрезаются (та же настройка, что на странице LLM) |
| `prompt.reminderEvery` | 8 | 0–100 | Напоминание правил каждые N сообщений | каждое N-е сообщение пользователя несёт 2 строки правил (`Prompts.REMINDER`); 0 — выключено |
| `tools.groups` | true | да/нет | Инструменты по требованию | выкл — все инструменты в каждом запросе (как до групп); вкл — ядро и нужные группы, остальное подключается словами запроса, историей или `tools_enable` (`ToolRouter`, `docs/SPEED.md` 8e) |
| `tools.fullEvery` | 0 | 0–100 | Все инструменты каждые N запросов | при включённых группах каждый N-й запрос пользователя несёт ВСЕ инструменты; 0 — никогда, 1 — каждый (счёт тот же, что у напоминания правил) |
| `skills.suggest` | true | да/нет | Подсказки навыков | короткая подсказка о подходящем навыке (`SkillHint`) |
| `home.suggestions` | true | да/нет | Подсказки на главной | LLM-подсказки на главном экране (`Suggestions.ENABLED`) |

Файл `triggers.json` (в домашнем каталоге приложения) — фразы-триггеры, страница «Фразы-триггеры» (`TriggersPage`).

## Как считается размер
* Части запроса: «Правила и окружение» (стабильный текст `Prompts.system` без памяти, навыков и сведений), «Память и стиль»,
  «Навыки (индекс)», «Сведения о пользователе и музыке», «Время, плеер, подсказки» (блок `[контекст: …]`), «Инструменты (N)»
  (схемы `ToolSpec` как отправляются), «История (N сообщ.)» (после обрезки по `llm.contextChars`).
* Токены — оценка: кириллица 3,2 символа на токен, остальное 4 (`PromptReport.tokens`). Точный подсчёт модели не делается.
* Полоса = доля окна, которую занимает часть. Если запрос больше окна, процент больше 100.

## Кнопки
* «Показать системный промпт» — только чтение, выделяемый текст (`Dialogs.sheet`).
* «Сбросить правила к умолчанию» — возвращает семь ключей выше к значениям по умолчанию после подтверждения.
  Текст правил в коде не редактируется (правил-переопределений в приложении нет), поэтому сбрасываются именно эти
  настройки.

## Напоминание правил
* Правила, которые владелец просит держать чаще всего: короткий ответ без markdown и честность о результате инструмента
  (`Prompts.REMINDER`). Попадают только в блок `[контекст: …]` текущего сообщения (`AgentRunSpec.userContext`), системный
  промпт и история не меняются, поэтому префикс кэша провайдера совпадает до дня напоминания (`PromptsReminderTest`).
* Номер хода считается по сообщениям пользователя видимой части сессии (`ChatStore.userTurns`, после «очистить контекст» счёт начинается заново).
* Тот же номер хода решает, какой запрос несёт полный список инструментов (`tools.fullEvery`): при N = 5 это запросы 5, 10, 15 …; в отчёте «Следующий запрос к модели» строка «Инструменты» показывает, чем уйдёт СЛЕДУЮЩИЙ запрос.

## Поиск по прошлым чатам (X-04)
* Инструмент `session_search(query, limit?, days?)`, только чтение. В системном промпте одна строка: «Если пользователь ссылается на прошлый разговор — сначала session_search».
* Индекс FTS5 (`item_fts`) создаётся миграцией до версии 3 вместе с триггерами; если модуля FTS5 нет, поиск идёт
  LIKE-сканом последних 3000 сообщений тем же сопоставлением (`core/chat/SearchQuery`). Ё приравнено к е, последнее слово — префикс.
* Выдача: чат, сообщение, роль, время, фрагмент ±60 символов с выделенными словами (`SearchSnippet`, `SearchHitRow`).
