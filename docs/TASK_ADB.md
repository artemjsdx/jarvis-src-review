# TASK ADB — Wi-Fi ADB client in pure Java (pairing + connect + shell)

Owner dirs: `app/src/main/java/app/jarvis/core/adb/**`, tests `app/src/test/java/app/jarvis/core/adb/**`, ART checks `app/src/debug/java/app/jarvis/dev/checks/adb/**`, optional libs in `app/libs/*.jar` (see below).

Goal: Jarvis (an ordinary Android app, targetSdk 28, no root) must be able to talk to the **phone's own adbd (or another phone's) over Wi-Fi** using Android's "Wireless debugging": 1) one-time **pairing** with host:pairingPort + 6-digit code, 2) **connect** to host:connectPort, 3) run shell commands and get stdout/stderr/exit code, 4) disconnect, reconnect later without re-pairing. The user may type the data in settings or paste it to the agent in chat — the UI distinguishes *address*, *pairing port*, *pairing code*, *connect port*.

## API (frozen — implement exactly; create these files)
```java
package app.jarvis.core.adb;
public class AdbException extends Exception { public enum Kind { BAD_INPUT, NETWORK, TIMEOUT, PAIRING_REJECTED, WRONG_CODE, NOT_PAIRED, AUTH_DENIED, TLS, PROTOCOL, UNSUPPORTED, CANCELLED, REMOTE }
    public final Kind kind; public final String userMessage /*Russian, safe*/; public final String technical; ... }
public final class AdbShellResult { public final int exitCode; public final String stdout, stderr; public final long durationMs; public final boolean timedOut; }
public final class AdbStatus { public enum State { NOT_PAIRED, PAIRED, CONNECTING, CONNECTED, ERROR }
    public final State state; public final String host; public final int port; public final String device /* ro.product.model or banner */; public final String keyFingerprint; public final String lastError; }
public interface AdbApi {
    AdbStatus status();
    void pair(String host, int pairingPort, String pairingCode, CancelToken cancel) throws AdbException;      // stores key + peer, state PAIRED
    void connect(String host, int port, CancelToken cancel) throws AdbException;                              // state CONNECTED
    boolean reconnect(CancelToken cancel);                                                                    // last host/port from disk; false on failure
    AdbShellResult shell(String command, long timeoutMs, CancelToken cancel) throws AdbException;
    void disconnect();
}
public final class AdbClient implements AdbApi { public AdbClient(java.io.File stateDir, app.jarvis.core.log.Journal journal) {...} }
```
Persistence in `stateDir`: the RSA-2048 adb key (generate on first use; PKCS#8 private key file mode 600; the public key in adb's `AndroidPubKey` base64 format + " jarvis@localhost"), last endpoint JSON. Pairing codes and keys must never reach the journal (use `Redactor`).

## Protocol facts you must implement (verify against sources; the real `adb` client binary of Termux — `adb version` 35.0.2 — is available to test against)
**Pairing (Android 11+ `adb pair`)** — see AOSP `packages/modules/adb/pairing_connection/`, `pairing_auth/` and `adb/tls/`: TCP connect to pairing port → TLS 1.3 (client cert optional/self-signed; server cert self-signed; trust anything; **TLS keying material exporter** with label `"adb-label\0"`, 64 bytes, no context, is mixed into the password: `password = pairing_code_bytes || exported_key_material`) → **SPAKE2** (BoringSSL `spake2`, curve **Ed25519** group, M/N constants from BoringSSL `third_party/boringssl/src/crypto/curve25519/spake25519.c`, client = Alice with name "adb pair client\0", server = Bob "adb pair server\0", hash SHA-512, the password scalar derivation exactly like BoringSSL: `password_hash = SHA512(password)`, reduce mod L, **clear cofactor handling as in BoringSSL**) → shared key; derive the AES-128-GCM key with **HKDF-SHA256** (info string `"adb pairing_auth aes-128-gcm key"`, salt none) → exchange `PeerInfo` (type `ADB_RSA_PUB_KEY`=0, 8192 bytes buffer containing the `AndroidPubKey` NUL-terminated) encrypted with AES-128-GCM (12-byte nonce = counter little-endian, incrementing per message direction, empty AAD). Message framing: `PairingPacketHeader{version=1 (uint8), type (1=SPAKE2_MSG, 2=PEER_INFO), payload size (uint32 big-endian)}` followed by payload. If decryption fails on either side the code was wrong → `WRONG_CODE`.
  Java has no SPAKE2/Ed25519 point arithmetic in its public API: **implement Ed25519 group operations yourself** with `BigInteger` (extended coordinates, correct decompression/compression, scalar multiplication, `8*` cofactor clearing where BoringSSL does it). Clean-room is fine; mirror BoringSSL's algorithm exactly (including how `my_msg = x*B + w*M` / `w*N` and the transcript hash `SHA512(len(my_name)||my_name||len(their_name)||their_name||len(my_msg)||my_msg||len(their_msg)||their_msg||len(key)||key||len(password_hash)||password_hash)` ordering — check against the BoringSSL source/docs you can fetch from GitHub: `https://raw.githubusercontent.com/google/boringssl/master/crypto/curve25519/spake25519.cc` (or the `.c` of older revisions) and AOSP `https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/pairing_auth/pairing_auth.cpp`). Tools like `curl`/`webfetch` work; googlesource may need `?format=TEXT` (base64). Also useful reference implementations: Shizuku's `AdbPairingClient`/`PairingContext` (native), MuntashirAkon `libadb-android` (`io.github.muntashirakon.adb`).
  **TLS exporter on Android:** `SSLSocket.exportKeyingMaterial` exists only in Conscrypt. On Android the platform copy is `com.android.org.conscrypt.Conscrypt` (hidden). Preferred: bundle `org.conscrypt:conscrypt-android` (download the AAR from Maven Central, put `classes.jar`→ dex via a jar in `app/libs/` and the `jni/<abi>/libconscrypt_jni.so` into `app/jniLibs-src/<abi>/` — tell the lead the exact layout; arm64-v8a and armeabi-v7a only) and use `org.conscrypt.Conscrypt.exportKeyingMaterial(SSLSocket, label, context, length)` with `Conscrypt.newProvider()` for the TLS 1.3 handshakes (on desktop JVM tests the `conscrypt-openjdk-uber` jar from Maven Central supplies the same API: keep that jar only under `.cache/testlibs`). Design `TlsExporter` so the provider choice is isolated.
**Connect (Android 11+ wireless debugging)**: TCP to the connect port; ADB message framing (24-byte header: command, arg0, arg1, data_length, data_check, magic; little-endian); send `CNXN` (version 0x01000001, maxdata 1 MiB (use 256 KiB), banner `host::features=shell_v2,cmd,stat_v2,...`); the device answers `STLS` (arg0=version): reply with `STLS`, then upgrade the socket to **TLS 1.3 with a client certificate** — a self-signed X.509 built from the same RSA key (write a minimal DER cert builder: you cannot use BouncyCastle on Android; sign with `SHA256withRSA`) — adbd accepts it iff the key was paired before. After the handshake the device sends its `CNXN` (banner `device::ro.product.model=…;features=…`). If the key is unknown the TLS handshake or the next read fails → `NOT_PAIRED`. (Classic non-TLS `AUTH` flow for `adb tcpip 5555` devices: implement `AUTH_TOKEN` → sign with the RSA key (`SHA1withRSA` on the raw 20-byte token using the ASN.1 prefix, i.e. `Signature "NONEwithRSA"` over DigestInfo like the adb host does) → `AUTH_SIGNATURE`, then `AUTH_RSAPUBLICKEY`; the user must tap "Allow" on the device — surface `AUTH_DENIED` after a 30 s timeout.)
**Shell**: `OPEN` local-id with destination `shell,v2,raw:<command>\0` if the device banner lists `shell_v2` (separate stdout/stderr packets + exit code packet; packet = 1-byte id (1 stdout, 2 stderr, 3 exit, 0 stdin, 4 close stdin) + uint32 LE length + data), else `shell:<command>\0` (combined output, no exit code → append `; echo __JV_EXIT:$?` and parse). Handle `OKAY`, `WRTE` (reply `OKAY`), `CLSE`, flow control (`maxdata`), timeouts (kill by closing the stream: send `CLSE`), cancellation, large outputs (cap at 256 KB per stream, mark truncated).

## How to test without a second phone
1. JUnit (JVM): crypto unit tests (Ed25519 group laws, SPAKE2 round trip client↔your own server implementation, HKDF/GCM), ADB framing, DER cert parse-back with `CertificateFactory`, `AndroidPubKey` encoding vs the output of `adb keygen`-compatible known vectors (generate a key with Termux's `adb` — `ADB_VENDOR_KEYS`/`~/.android/adbkey.pub` — and compare your encoder's output for the same private key byte for byte).
2. **Interop with the real `adb` binary** (strongest check): write a Java test-tool `FakeAdbd` (under `app/src/test/java/.../adb/`) implementing the **server side** of pairing (listens on a port, TLS server with a self-signed cert, SPAKE2 as Bob, same exporter, PeerInfo exchange) and the server side of the connect protocol (CNXN/STLS/TLS server requiring a client cert, OPEN shell → run the command with `/system/bin/sh -c` locally and answer shell_v2 packets). Then: `adb pair 127.0.0.1:<port> <code>` (Termux's real client, adb server auto-starts on 5037) must succeed against FakeAdbd, and `adb connect 127.0.0.1:<port>` + `adb -s 127.0.0.1:<port> shell echo hi` must work. Use a wrong code and confirm the real adb reports a failure. Then run **your own client** against the same FakeAdbd. If the real client interoperates with your server half of SPAKE2, the primitives are right.
3. ART: `tools/art-apk.sh` a check that runs the client against FakeAdbd running in a separate JVM (`java -cp build/test/main:build/test/test ...`) on 127.0.0.1 to prove the code works on Android's runtime and TLS stack (Conscrypt from the platform or bundled).
Be explicit in the final report about what is proven (interop with real adb on loopback) and what cannot be proven here (real adbd on a device, Android's wireless-debugging UI flow, key trust prompts, mDNS discovery).
