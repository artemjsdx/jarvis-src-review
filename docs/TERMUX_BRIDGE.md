# Мост в Termux (`termux_exec`)

Агент и режим «Termux» в терминале запускают команды в настоящем Termux: python3, git, node, curl, apt.
Мост использует штатный сервис Termux `RUN_COMMAND`; никаких root-прав и правок Termux не нужно.

## Как работает

1. Приложение шлёт в `com.termux/com.termux.app.RunCommandService` intent `com.termux.RUN_COMMAND`:
   путь `/data/data/com.termux/files/usr/bin/bash`, аргументы `-lc <строка>`, рабочий каталог — домашний Termux, фоновый режим.
2. К запросу прикладывается PendingIntent на `TermuxResultReceiver` (не экспортируется). Termux присылает результат
   в extra `result` (`stdout`, `stderr`, `exitCode`, `err`, `errmsg`). Ответ сопоставляется с ожидающим вызовом по id в URI intent.
3. Сама команда передаётся в base64 (текст, stdin и каталог), поэтому кавычки, `$`, переводы строк и кириллица не ломают строку.
   Команда выполняется через `timeout -k 5 <сек> bash -c …`: по таймауту всё дерево процессов получает TERM, затем KILL.
   Код 124 означает таймаут.
4. Отмена (кнопка «Стоп» или отмена хода агента) и отсутствие ответа: отправляется второй запрос
   `pkill -TERM`/`-KILL` по маркеру `jv-req-<id>`, который есть в командной строке всех процессов запроса.
5. Вывод обрезается как у `shell_exec`: 48 КБ (начало и конец, середина помечается). Команда и stdin вместе до 64 КБ.

## Включить (владелец)

1. В Termux: `~/.termux/termux.properties` → строка `allow-external-apps = true`, затем `termux-reload-settings` или перезапуск Termux.
2. В Jarvis: **Настройки → Песочница и инструменты → Мост в Termux → «Выдать»** (разрешение `com.termux.permission.RUN_COMMAND`).
3. Там же нажмите **«Проверить»**: должна появиться строка `jarvis-ok · Linux … · Python 3.x`.
4. Инструмент `termux_exec` регистрируется при запуске приложения, если Termux установлен. Установили Termux позже: перезапустите Jarvis.

Без шагов 1–2 агент получит понятную ошибку, а в терминале режим «Termux» не включится.

## Ограничения (честно)

- Android 12+ запрещает запуск сервисов из фона: если приложение не на переднем плане и не имеет активной службы,
  `startService` может быть отклонён. Тогда агент получит текст «Android не разрешил запуск Termux из фона» — откройте Jarvis и повторите.
- Вывод приходит целиком по окончании команды; потокового вывода (как в обычном терминале) нет.
- Интерактивный ввод не поддерживается (stdin задаётся заранее параметром `stdin`).
- Отмена убивает процессы, которые остались в группе `timeout`; процессы, которые сами ушли в другую группу, могут пережить отмену.
- Команды выполняются с правами Termux, а не Jarvis: они видят домашний каталог Termux и всё, до чего дотягивается Termux.
- Текст команды не пишется в журнал самим мостом; общий журнал вызовов инструментов работает как для остальных инструментов.

## Параметры инструмента `termux_exec`

| параметр | тип | по умолчанию | описание |
|---|---|---|---|
| `command` | строка, обязательно | — | команда bash, можно несколько строк |
| `cwd` | строка | домашний каталог Termux | рабочий каталог внутри Termux |
| `stdin` | строка | пусто | данные на stdin команды |
| `timeout_s` | целое | 60 (макс. 600) | таймаут, сек |

Ответ: `exit_code`, `stdout`, `stderr`, `duration_ms`, при необходимости `timed_out`, `output_truncated`.
Ошибки моста (Termux не установлен, нет разрешения, Android запретил запуск, Termux не ответил) возвращаются текстом.

## Файлы

- `app/src/main/java/app/jarvis/core/tools/TermuxCommand.java` — построение строки запуска и команды остановки (чистая Java, тесты).
- `app/src/main/java/app/jarvis/core/tools/TermuxTool.java` — инструмент `termux_exec`, таймауты, разбор ответа.
- `app/src/main/java/app/jarvis/rt/TermuxBridge.java` — транспорт на Android (intent, PendingIntent, ожидание ответа).
- `app/src/main/java/app/jarvis/rt/TermuxResultReceiver.java` — приём результата.
- Тесты: `TermuxCommandTest` (реальный bash, timeout и pkill на хосте), `TermuxToolTest` (фейковый транспорт).
