# Модели: возможности, параметры, смена модели (S-05, S-06, S-07, X-02)

## Откуда берутся данные
Каждое значение (окно контекста, максимум ответа, инструменты, температура, уровни рассуждений, изображения, цена) имеет источник.
Порядок, по которому значения заполняют друг друга (`ModelCaps.fill`):

1. **provider** — собственный `GET /models` провайдера. Есть у OpenRouter, DeepSeek (нужен ключ), Groq, Mistral; у большинства остальных только `id`.
2. **openrouter-catalog** — публичный `GET https://openrouter.ai/api/v1/models` (без ключа). Совпадение по полному id (`deepseek/deepseek-v4-flash`) или по части после «вендора»: прямой DeepSeek `deepseek-v4-flash` и `inception/mercury-3` у Inception находят свои записи.
3. **builtin** — `BuiltinModels`: только значения, которые провайдер реально вернул (DeepSeek `deepseek-flash`, `deepseek-v4-pro`, наблюдение 2026-10-29). Выдуманных значений нет.
4. **learned** — что провайдер отказался принимать (`ParamMemory`). Перекрывает всё остальное: параметр больше не отправляется.

Записи провайдера, которые не несут данных, помечаются `source=unknown`.

## Как показывается «неизвестно»
* Неизвестное значение никогда не показывается как «нет». Чип: «инструменты: неизвестно», «контекст неизвестен».
* Уровень рассуждений, которого нет в списке модели, при неизвестном статусе помечается «неизвестно — попробуйте, ошибка попадёт в журнал».
* Уровень, который модель точно не принимает (есть список уровней и его нет в нём, либо `reasoning=NO`), выключен, по нажатию объясняется.
* Температура: если провайдер сообщает `temperature=NO`, ползунок заменён пояснением, параметр не отправляется.
* Максимум ответа: значение обрезается до лимита модели, лимит пишется под полем.

## Кэш и загрузка (`ModelCatalog`)
* Файлы: `filesDir/models/<provider>.json` (список и возможности), `filesDir/models/params.json` (отказы параметров).
* Срок 24 часа. Чтение никогда не ждёт сеть: отдаётся кэш, а обновление идёт в фоне (stale-while-revalidate).
* Одна загрузка на провайдера одновременно. После ошибки повтор не раньше чем через 10 минут.
* Ошибка пишется в журнал (категория `llm`, уровень ERROR, HTTP-статус и техническая строка) и показывается в карточке модели.
* Провайдер с ключом без ключа не опрашивается: в журнал пишется «Нужен API-ключ».

## Параметры и отказы (`ParamMemory`)
* `OpenAiClient` при ответе 400 про параметр убирает его и повторяет запрос. Тогда `ParamMemory.learn(provider, model, param)` запоминает отказ (в файле, между запусками) и пишет строку журнала «параметр X не поддерживается моделью Y: больше не отправляю».
* Память — по паре «провайдер + модель», а не глобально, как было раньше.
* Что запоминается: `temperature`, `max_tokens`, `reasoning_effort`, `reasoning`, `thinking`, `enable_thinking`, `tool_choice`, `stream_options`, `realtime`, `strict`.

## Уровни рассуждений
`off | instant | low | medium | high | max` и «Авто» (пусто). Отправка по провайдеру (`OpenAiClient.applyReasoning`): DeepSeek получает переключатель `thinking` и `reasoning_effort` с выбранным уровнем (флаг `Quirks.sendEffort`); остальные провайдеры по-прежнему получают только свой переключатель. Уровень, которого модель не принимает, не отправляется, а запрос идёт на «Авто».

## Контекст: «Авто» и ручной режим
* `llm.contextAuto` = true по умолчанию: `min(окно модели, 200 000 токенов) − ответ` × 3,2 символа на токен (`ContextFit.autoContextChars`). Неизвестное окно — 60 000 символов, как раньше.
* Ручной режим (`llm.contextAuto` = false) берёт `llm.contextChars`.
* Оценка токенов в переписке: символы / 3,2.

## Смена модели (X-02, `ui/settings/llm/ModelSwitch`)
Смена через любой выбор: карточка модели, «Недавние», список провайдеров, список моделей, кнопка в чате (`ModelSheets`).

1. Realtime / голосовые / TTS / STT / audio-модели (по id) не выбираются: объяснение, без смены.
2. Видимая переписка активной сессии (до 400 элементов) оценивается по окну новой модели (`ContextFit.check`).
3. Если всё помещается и инструменты не запрещены — тихая смена, тост «Модель: …» (с пометкой, если инструменты неизвестны).
4. Иначе вопрос с причинами простыми словами и тремя кнопками:
   * «Переключить и обрезать старое» — смена; старое, не влезающее в окно, не попадает в запрос (бюджет `contextChars`);
   * «Передать краткое резюме» — текущей моделью (один запрос без потока, ≤ 1500 знаков, `ContextSummarizer`), затем `Sessions.clearContext` и системный элемент «Резюме предыдущего контекста: …», который `ChatStore.history` отдаёт модели; последние 4 сообщения в резюме не входят;
   * «Отмена».

Что реально переносится: веса и внутреннее состояние модели не переносятся. Текст истории отправляется заново, поэтому любая текстовая модель продолжит разговор. Ограничения: меньшее окно, другой формат вызова инструментов и рассуждений, у голосовых моделей другой протокол (их не выбираем). Первый запрос после смены медленнее: у провайдера нет кэша префикса.

Картинки в запросы сейчас не передаются (вложения уходят текстом с путём), поэтому потеря «изображений» только информирует.

## Агент: шаги
`llm.maxSteps`: 0 = без ограничения. Жёсткий предел 200 (`StepLimit`), в журнал пишется строка при запуске запроса. Вручную — от 2 до 30.

## Ключи настроек
| Ключ | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `llm.provider` | строка | `inception` | текущий провайдер |
| `llm.model`, `llm.model.<provider>` | строка | из подсказок провайдера | текущая модель |
| `llm.recent` | список `provider|model` | пусто | последние 8 выбранных пар, новые первыми |
| `llm.contextAuto` | bool | `true` | «Авто» размер контекста |
| `llm.contextChars` | int | `60000` | ручной размер контекста (символы) |
| `llm.maxTokens` | int | `4000` | максимум токенов ответа; обрезается до лимита модели |
| `llm.maxSteps` | int | `10` | шаги агента; `0` = без ограничения |
| `llm.reasoning` | строка | `low` | уровень рассуждений (`""` = Авто) |
| `llm.temperature` | float | (нет) | температура; отсутствие = Авто |
| `llm.fallbacks` | список | `openrouter` | запасные провайдеры |

Файлы: `models/<provider>.json`, `models/params.json` (в приватном каталоге приложения, секретов нет).
