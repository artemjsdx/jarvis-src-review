# Проверка на устройстве — files1 (Файлы, Терминал, мост Termux)

Не выполнено: телефон недоступен по ADB (владелец в пути). Все пункты ниже нужно пройти на варианте `app.jarvis.files1`.

Сборка и установка (с телефона или через ADB, когда он будет доступен):
```
export ANDROID_ADB_SERVER_PORT=5038; D=10.61.19.159:38569
JV_APP_ID=app.jarvis.files1 JV_APK_OUT=$PWD/build/outputs/files1.apk bash build.sh debug
adb -s $D install -r build/outputs/files1.apk
adb -s $D shell pm grant app.jarvis.files1 com.termux.permission.RUN_COMMAND
```
Во всех шагах с открытием приложения использовать `bash tools/with-screen.sh <команда>`.

## Файлы (F-01..F-05)
1. Открыть «Файлы». Ожидание: корень показывает карточки папок с числом элементов, «Файлы в корне» если есть; «песочница» в хлебных крошках внутри рамки.
2. Открыть `work/` с несколькими файлами. Ожидание: строки с иконкой, именем, размером и датой; разделители между строками; без «Пустая папка».
3. Нажать «Обновить» (стрелка справа). Ожидание: иконка вращается ~0,7 с, затем тост «Обновлено: N».
4. Открыть пустую папку (`tmp/пустая`). Ожидание: «Пустая папка» с подсказкой, без карточек корня.
5. Нажать «Скачать по ссылке», вставить короткую ссылку на небольшой файл (например, https-ссылку на текст до 1 КБ). Ожидание: диалог загрузки, затем «Скачано: …», файл в `downloads/`.
6. Ввести `ftp://example` в диалог. Ожидание: «Нужна ссылка http:// или https://».
7. Открыть PDF (например, `docs/тестовый-документ.pdf`). Ожидание: первая страница, «Страница 1 из 2», кнопки «Назад»/«Дальше» переключают страницы; «Назад» на первой неактивна.
8. Открыть `.md` или `.txt`. Ожидание: текстовый редактор, как раньше.
9. Долгое нажатие на файл → «Переименовать», «Удалить». Ожидание: действия работают, список обновляется.

## Терминал (T-01..T-03)
10. Открыть «Терминал». Ожидание: вывод в рамке; быстрые команды (`ls`, `pwd`, `df -h`, `uname -a`, `ps`, `date`) ВЫШЕ строки ввода; справа иконка «i».
11. Нажать «i». Ожидание: шторка «Быстрые команды» с описанием каждой команды.
12. Ввести `uname -a` и нажать «Пуск». Ожидание: вывод, разделитель `── exit 0 · … ──` с длительностью; кнопка «Пуск» той же высоты, что строка ввода.
13. Ввести `sleep 5`, во время работы «Стоп». Ожидание: разделитель «отменено · …», кнопка возвращается в «Пуск».
14. Стрелки вверх/вниз по истории. Ожидание: команда подставляется в строку ввода.
15. Скриншот в светлой и тёмной теме: рамки тонкие, не обрезаются.

## Мост Termux (T-04, T-05)
16. Предусловие: в Termux `allow-external-apps = true`; Termux установлен.
17. «Песочница и инструменты». Ожидание: «Termux — установлен», «Разрешение моста — выдано».
18. Нажать «Проверить». Ожидание: `jarvis-ok · Linux … · Python 3.x` (или версия Python из Termux).
19. Переключить терминал в режим «Termux» (чип «Shell» → «Termux»). Ввести `python3 --version`. Ожидание: версия Python, разделитель `Termux exit 0`.
20. В режиме Termux ввести `git --version` и `node --version`. Ожидание: версии; если node не установлен — `exit 127` и текст ошибки.
21. Агент: «запусти в Termux `printf 'a\nb\n' | wc -l`». Ожидание: вызов `termux_exec`, stdout `2`, `exit_code 0`.
22. Агент: `termux_exec` с `stdin` «строка 1\nстрока 2» и командой `cat`. Ожидание: stdout совпадает с входом.
23. Агент: `termux_exec` командой `sleep 60` и `timeout_s` 5. Ожидание: ошибка «Таймаут», `timed_out: true`, вызов завершается за ~6–8 с.
24. Агент: `termux_exec` командой `exit 3`. Ожидание: ok=false, `exit_code 3`, текст «завершилась с кодом 3».
25. Отмена: в режиме Termux запустить `sleep 100` и нажать «Стоп». Ожидание: «отменено»; в Termux `ps | grep sleep` больше ничего не показывает.
26. Без разрешения (`adb shell pm revoke app.jarvis.files1 com.termux.permission.RUN_COMMAND`): вызов `termux_exec` возвращает текст «Termux недоступен … разрешение моста»; в режиме Termux Jarvis просит разрешение.
