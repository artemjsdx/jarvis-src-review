# Как писать навыки (SKILL.md)

Навык — это процедура, которую новый экземпляр ассистента может выполнить без повторного обучения. Формат совпадает с Hermes и agentskills.io. Документ нужен и тем, кто пишет навыки руками, и самому ассистенту (навык `writing-skills`).

## Где лежат

Песочница: `skills/<имя>/SKILL.md`. Дополнительно: `skills/<имя>/references/`, `templates/`, `scripts/`, `assets/` (других папок нет). Имя навыка: строчные латинские буквы, цифры, «-» и «_», до 64 символов; совпадает с именем папки и полем `name`.

Ограничения: SKILL.md до 20 КБ; весь навык до 200 КБ; один дополнительный файл до 64 КБ; навыков до 100. Нарушение — ошибка, ничего не сохраняется.

## Шапка

```
---
name: room-lights
description: "Используй, когда пользователь просит включить или выключить свет в комнате. Работает через ADB-команды."
version: 1.0.0
tags: [adb, home]
requires_tools: [adb_status, adb_shell]
---
```

- `description` — главное поле: по нему ассистент решает, загружать ли навык. Формат: «Используй, когда <триггер>. <что делает>.», до 300 символов. Не название категории («Умный дом» — неверно).
  - Верно: «Используй, когда пользователь просит включить или выключить свет в комнате. Работает через ADB-команды.»
  - Неверно: «Управление светом.» (нет триггера), «Use when…» без поведения, «Полезные команды» (категория).
- `name` должен совпадать с папкой.
- `tags`, `requires_tools`, `version` необязательны. `requires_tools` перечисляет инструменты, без которых навык не работает.

## Тело: обязательные разделы

1. `## Когда применять` — две-три фразы: какая задача и что отличает её от похожих.
2. `## Предусловия` — что должно быть готово: подключение ADB, права, установленное приложение, данные пользователя.
3. `## Шаги` — нумерованный список. Каждый шаг — точный вызов инструмента с реальными аргументами, например `adb_shell {"command":"getprop ro.product.model"}`. Не «проверь телефон», а команда и ожидаемый результат.
4. `## Как проверить результат` — как убедиться, что действие сработало. Не «ответ ok», а конкретное условие.
5. `## Ловушки` — ошибки, которые уже случались или очевидно случатся. Одна ловушка — одна строка с причиной.
6. `## Откат` — как вернуть всё назад. Если откат не нужен (чтение), так и написать.

## Правила уроков

- Пиши уроки, а не журнал. «Нужен флаг -p, иначе broadcast уходит всем приложениям» — урок. «Вчера в 14:20 не сработало» — журнал: в навык не пишется.
- Императивное правило и причина. Без дат, номеров задач, имён людей из переписки.
- Одно правило на урок.
- Нельзя сохранять пароли, коды сопряжения, токены, адреса с ключами.
- Сначала дополняй существующий навык (`patch`), потом создавай новый. Перед созданием вызови `skills_list`.
- Не пересказывай весь вывод команды: в навык идёт то, что нужно повторить.

## Как сохранять (инструмент skill_manage)

Один вызов — массив операций, он атомарен: если одна операция упала, сохранения не будет вовсе.

```
skill_manage {"operations":[{"action":"create","name":"room-lights","content":"---\nname: room-lights\n…полный SKILL.md…"}]}
```

- `create` — полный текст SKILL.md; навыка ещё нет.
- `patch` — точечная замена: `old_string` должен встречаться один раз (иначе `replace_all: true`). Полный `content` у patch переписывает всё: только если меняется почти весь файл. Перед patch читай навык через `skill_view`, чтобы копировать текст точно.
- `write_file` / `remove_file` — файлы в `references/`, `templates/`, `scripts/`, `assets/`.
- `delete` — только единственной операцией в батче.

Ассистент предлагает сохранить навык после сложной задачи (4 и больше вызовов инструментов или восстановление после ошибки), не чаще раза в 30 минут и не в голосовом режиме. Пользователь решает. Если загруженный навык оказался неполным, ассистент обязан исправить его через `patch` до завершения задачи.

## Как ассистент загружает навык

В системном промпте лежит только индекс: «имя — description» для каждого навыка и три правила. Полный текст ассистент получает через `skill_view` (имя навыка) и следует ему. Поэтому описание должно точно говорить, когда навык нужен: по нему принимается решение.

## Пример 1: управление подсветкой комнаты через ADB

Это образец структуры. Имена пакетов и интентов ниже — плейсхолдеры: при создании навыка подставляй то, что нашёл сам на этом телефоне (шаг 2). Не копируй их как есть.

```
---
name: room-lights
description: "Используй, когда пользователь просит включить или выключить свет в комнате. Работает через ADB-команды, если ADB подключён."
version: 1.0.0
tags: [adb, home]
requires_tools: [adb_status, adb_shell]
---

## Когда применять
Пользователь говорит «включи свет», «выключи свет в комнате», «сделай свет тусклее».

## Предусловия
- adb_status показывает соединение (state «connected»). Если нет, сначала навык adb-wifi-pairing.
- Известен пакет приложения лампы. Если не известен, найти: шаг 2.

## Шаги
1. `adb_status` — если не подключено, остановись и попроси подключить ADB (навык adb-wifi-pairing).
2. Найти приложение лампы, один раз, и запомнить имя пакета в memory_save (ключ «пакет лампы»):
   `adb_shell {"command":"cmd package list packages | grep -i -E 'light|lamp|smart'"}`
3. Включить: `adb_shell {"command":"am broadcast -p <пакет лампы> -a <интент включения> --es room bedroom --ei brightness 255"}`
4. Выключить: та же команда с `--ei brightness 0`.
5. Ответить одной фразой по результату: «Свет включён», только если exit_code 0.

## Как проверить результат
exit_code 0 у `am broadcast` НЕ доказывает, что свет изменился: команда успешна, даже если получателя нет. Проверка: спросить пользователя «Свет загорелся?», либо, если приложение пишет состояние, прочитать его через `fs_read`. Без этого не говори «свет включён» как факт.

## Ловушки
- Без `-p <пакет>` broadcast уходит всем приложениям: лишний эффект.
- `am broadcast` возвращает «Broadcast completed» даже без получателя. Поэтому см. «Как проверить».
- Команда выполняется через ADB, пока соединение живо. После перезагрузки телефона ADB надо подключить заново.
- Интент и его extra-параметры зависят от приложения: угаданные значения дают тишину, а не ошибку.

## Откат
Противоположная команда: выключить, если включали. Не трогать чужие пакеты.
```

Что здесь важно для нового экземпляра: команды с реальными аргументами, шаг проверки без слепого доверия exit_code, ловушка про broadcast.

## Пример 2: утренняя сводка

```
---
name: morning-briefing
description: "Используй, когда пользователь просит утреннюю сводку или «что там сегодня». Собирает время, погоду из адреса, который назвал пользователь, и короткий список дел, без чтения всех данных вслух."
version: 1.0.0
tags: [daily]
requires_tools: [memory_get, http_fetch, fs_read]
---

## Когда применять
Утренний запрос «что сегодня» или «сводка» без уточнений, обычно до 10 часов.

## Предусловия
- В памяти есть факты о пользователе: город или адрес сервиса погоды (memory_get). Если нет, спроси один раз и сохрани через memory_save.
- Список дел, если он есть, лежит в файле docs/tasks.txt (проверь через fs_read).

## Шаги
1. `memory_get` без ключа: прочитать факты (город, предпочтения по времени).
2. Параллельно (один ответ модели): `http_fetch` по адресу сервиса погоды, который записан в памяти, и `fs_read {"path":"docs/tasks.txt"}`.
3. Если погода не пришла (ok=false), скажи об этом одной фразой и продолжай.
4. Ответь 2–3 предложениями: день недели, температура, главное из дел. Больше трёх дел не перечисляй.

## Как проверить результат
В ответе есть температура только если она пришла из http_fetch с ok=true. Цифры не выдумывай.

## Ловушки
- Не читай весь список дел вслух: голос медленный, пользователь просил сводку, а не протокол.
- Если утро тихое по настройкам (в памяти записано «не звонить до 9:00»), не начинай речь раньше времени, которое задал пользователь.
- Ответ озвучивается: без списков и markdown.

## Откат
Не применимо: навык только читает данные.
```

Что здесь важно: данные берутся из памяти и инструментов, а не из головы; при сбое части данных ассистент говорит о ней и продолжает.

## Проверка навыка

После создания: `skill_view` с именем должен вернуть текст без ошибок; `skills_list` — показать навык с описанием. Если навык не загружается ассистентом, почти всегда причина в `description`: он не называет триггер.
