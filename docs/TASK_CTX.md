## Deliver
### A. Skills (new package `core/skills/**`, tools registered from `rt/SkillTools.java`)
1. Format = Hermes/agentskills.io: a directory per skill in the sandbox `skills/<name>/SKILL.md` with YAML front matter (`name`, `description`, optional `version`, `tags`, `requires_tools`) + markdown body; optional `references/`, `scripts/`, `assets/` files. Name: lowercase, hyphen/underscore, ≤ 64. **Description rule (copy Hermes): "Use when <trigger>. <behaviour>." ≤ 300 chars**, never the category name.
2. `SkillStore`: parse (own tolerant mini YAML for the 4–5 keys; no library), validate, list, view, create, patch (targeted `old_string`→`new_string`, preferred; full rewrite only as last resort), delete, write_file/remove_file under `references|scripts|assets|templates` only (path traversal impossible), size limits (SKILL.md ≤ 20 KB, total ≤ 200 KB/skill, ≤ 100 skills), atomic writes, journal entries. Import/export a skill as a zip (zip-slip safe: `ZipSafe` exists).
3. Tools for the agent: `skills_list()` (name + description + path), `skill_view(name, file?)`, `skill_manage(operations[])` with Hermes' call shape (array of ops `{action: create|patch|delete|write_file|remove_file, name, ...}`, atomic: any failure rolls back all), all with Russian descriptions + the Hermes rules in the tool description ("write lessons, not logs: imperative rule + why; no dates/incident narration; one rule per lesson; patch instead of rewrite").
4. System prompt integration WITHOUT bloating it: `SkillStore.indexText(maxChars=1200)` → `<available_skills>` list of "name — description" lines (+ a 3-line instruction: "Перед ответом просмотри список; если навык подходит хотя бы частично — загрузи его skill_view и следуй ему. После сложной или итеративной задачи предложи сохранить навык. Если загруженный навык оказался неполным или неверным — исправь его skill_manage(patch)."). Expose it through `Prompts.Info.skills` (additive field; one additive line in `Prompts.system` — `speed2` is restructuring that file: keep your edit tiny and say so in the report).
5. **Offer-to-save flow** (the Hermes "grows with you" loop): after an agent run that used ≥ 4 tool calls or that recovered from an error, the runner adds ONE hidden system hint to the NEXT user turn: "[подсказка] В прошлом запуске было N вызовов инструментов. Если это переиспользуемая процедура, предложи пользователю сохранить её как навык (одной фразой)". Rate-limit: not more than once per 30 min, never during voice turns unless the user asked; setting `skills.suggest` (default on). When the user agrees, the model calls `skill_manage(create)` with a body that follows the template below. Provide `docs/SKILL_AUTHORING.md` = the exact authoring rules + template + 2 worked examples in Russian (one: "управление подсветкой комнаты через ADB-команды": preconditions, exact commands, how to verify, pitfalls; two: "утренняя сводка"), so that a NEW agent can execute the skill without re-learning: sections `## Когда применять`, `## Предусловия`, `## Шаги` (numbered, exact tool calls/commands with real arguments), `## Как проверить результат`, `## Ловушки` (pitfalls found), `## Откат`.
6. Seed skills shipped as assets (`app/assets/skills/<name>/SKILL.md`, copied to the sandbox on first run if absent, never overwritten): `termux-environment` (how to use termux_exec when available), `web-research` (parallel web_search → web_fetch → cite), `adb-wifi-pairing`, `writing-skills`. Real, concise, Russian.
7. JVM tests: parse/validate/patch/rollback/zip-slip/limits/index text size, tool schemas valid JSON, hint rate limiter.

### B. Memory v2 (`core/tools/MemoryStore.java` + prompt snippet)
1. Hard budget (default 2000 chars for the injected snippet, setting `memory.budget`); when full, `memory_save` returns `{ok:false, error:"память заполнена: объедините или удалите записи", usage:{used,limit}}` (never silently drops).
2. Entries are FACTS about the user/environment. Update the tool descriptions per Hermes `build_memory_guidance`: "declarative facts, not instructions: «Пользователь предпочитает короткие ответы» ✓ — «Всегда отвечай коротко» ✗; procedures and task-specific preferences belong in skills; a fact that is stale within a week does not belong in memory". Add `memory_replace(key, value)` semantic = existing save with update (keep) and `memory_pin(key, on)`; pinned entries are always injected first, others by recency until the budget is used (`promptSnippet` honours the budget and ranks pinned > recent).
3. Add `kind` to entries (`fact` | `preference` | `style`) so the UI can show icons (S-09/S-10): "style" = response style notes like "меньше точек в ответах" → these are injected as a separate line `СТИЛЬ ОТВЕТА ПОЛЬЗОВАТЕЛЯ:` (they ARE instructions from the user and are fine there); everything else under `ПАМЯТЬ ПОЛЬЗОВАТЕЛЯ:`. Backward compatible with the existing `memory.json` (migrate on load).
4. Tests: budget, ranking, migration from the old file format, style/fact split in the snippet, tool JSON results.
