# Проверка tools2 (группы инструментов по требованию): то, что не проверено на стенде

Что уже проверено без телефона: JVM-тесты (таблица из 58 команд, цикл агента на mock-сервере), реальный реестр на ART (`ToolGroupsCheck`), реальные токены и время до первого токена прямым запросом к провайдеру — `docs/SPEED.md`, раздел 8e.
Не проверено: ход целиком на настоящем приложении и поведение настоящей модели, когда роутер промахнулся. Шаги ниже идут через MCP-мост (`python3 tools/jv.py <инструмент> '<json>'`), без звука и без боковых вариантов приложения (правила владельца): в CI-эмуляторе (`tools/ci/gh.sh`) или на телефоне, когда владелец разрешит.

Размер запроса
1. `agent_prompt_dump '{}'`: `toolCount` ≈ 13 (ядро + `tools_enable` + MCP-инструменты владельца), `toolCountRegistered` ≥ 47, `chars.tools` ≈ 5,6 тыс. вместо ≈ 22,5 тыс. В `report` строка «Инструменты (13 из 49)».
2. `agent_tools_list '{"schemas":false}'`: у каждого инструмента есть поле `group` (`core` или имя группы); инструментов с неожиданным `core` быть не должно (кроме перечисленных в `ToolGroups.CORE_BUILTIN` и MCP).

Выбор групп (сессия `chat_new`, `chat_send` с `wait=true`; после каждого шага смотреть журнал `journal_tail '{"cat":"AGENT"}'` и `trace_recent`)
3. «расскажи анекдот»: журнал «Инструменты: 13 из N, группы: нет», в трассе `llm.tool_specs` = 13, `llm.tool_groups` = `[]`.
4. «включи Queen» (нет файла Queen, чтобы не играло): «группы: music (общий глагол «включи»), adb (…)»; модель вызывает `music_list`, честно отвечает, что трека нет.
5. «открой ютуб»: группа `adb`, модель вызывает `adb_shell` или честно говорит, что ADB не подключён (не «не умею»).
6. Липкость: «включи музыку», затем «ещё раз» (без слов про музыку): во втором ходу в журнале «music (в истории: music_play)»; через 3 хода без музыки группа снова не показывается.
7. Плеер играет, фраза «ну всё, надоело»: «music (плеер занят)», модель вызывает `music_stop`.

Промах роутера (главное, чего стенд не видел)
8. Придумать 5 просьб БЕЗ слов из таблицы `ToolRouterTest`, которым нужен инструмент скрытой группы (например, файл, но без слов «файл», «папка», «заметка», «документ»). Для каждой записать: вызвала ли модель `tools_enable`, сколько шагов заняла просьба, не ответила ли «не умею».
   Ожидание: `tools_enable` → следующий шаг → нужный инструмент. Если модель отвечает «не умею», записать точную фразу и модель: это основание добавить основу слова в `ToolRouter` или усилить строку в `Prompts.system`.
