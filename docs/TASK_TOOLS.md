# TASK tools1 — parallel web search, page fetch/reader, documentation library backend (W-01, W-02, W-03 backend)

Read first: `docs/AGENT_BRIEF.md` (Wave 2 + Wave 3 rules), `docs/BACKLOG.md` section W. Worktree/branch: `tools1`. No phone needed: pure Java core + JVM tests (MockServer on loopback), plus ONE live smoke test through the real network.

## Owner's words (translated)
"Add **parallel web search** for sure, and the ability to **download files from the internet, documentation, view them** — a full terminal basically." The agent must be able to search the web (several queries at once), open a page and read it as clean text, and download docs. Search backends other than the default are OPTIONAL and configured in the app (Tavily, Exa, Brave, SearXNG...).

## Deliver
1. `SearchBackend` interface + implementations, selected by `web.search.backend` = auto | openrouter | brave | tavily | exa | searxng | ddg:
   * **openrouter** (default when the OpenRouter key exists; no extra key): the request body gets `"plugins":[{"id":"web","max_results":N}]` (or model suffix `:online`) on a tiny cheap model; results come from the response `annotations` of type `url_citation` (title, url, content snippet). EVALUATE on the live network which cheap model + prompt returns clean citations fastest (candidates: `deepseek/deepseek-v4.1-flash`, `openai/gpt-5-nano`, `google/gemini-2.5-flash-lite`, `perplexity/sonar`); record latency and token usage per query in docs/WEB_TOOLS.md; max total spend for evaluation: 0.3 USD.
   * **brave / tavily / exa**: their documented REST APIs with the user's key (JSON in, JSON out; map to the common `SearchHit {title,url,snippet,source,published?}`); **searxng**: `<instance>/search?q=..&format=json`; **ddg**: `https://html.duckduckgo.com/html/?q=` scraping as a last resort (this network sometimes answers 202; handle it as "unavailable", do not loop).
   * `auto` order: configured paid backends (brave > tavily > exa) → openrouter → searxng → ddg; a backend failing with 401/402/403/429/5xx/timeout is skipped for 10 minutes and the next one is tried; the result says which backend answered.
2. Tool `web_search(queries: string[1..6], limit?: int=5, recency?: day|week|month|year, site?: string)` (sideEffects=false so the agent loop runs it in parallel with other read-only calls): runs ALL queries concurrently (own executor, per-query timeout 12 s, overall 20 s), de-duplicates URLs (normalise: strip tracking params, `www.`, fragments), keeps result order stable per query, returns `{ok, results:[{query, hits:[...]}], backend, ms}`; partial failures are reported per query, never swallow them. Cancellation-safe (`ToolContext.cancel`).
3. Tool `web_fetch(url, format?: markdown|text|raw, max_chars?: int=12000, offset?: int)`: HTTP GET with sane headers, redirects (max 5, https downgrade refused), size cap 3 MiB, charset detection (header, `<meta>`, BOM, fallback UTF-8/windows-1251), gzip. HTML → readable markdown: drop `script/style/nav/footer/aside/form/noscript/svg/iframe`, hidden elements, cookie banners (by common id/class words), pick the main content (`<article>`/`<main>`/largest text-dense block), keep headings, paragraphs, lists, links (as `[text](abs-url)`), code blocks, tables (as aligned text), image alt text. Return `{ok,url,finalUrl,title,status,contentType,text,truncated,nextOffset,links:[...top 30...]}`. JSON → pretty text; plain text as is; PDF/office/images/archives: do NOT try to parse; return `{ok:true, binary:true, hint:"используйте download, затем откройте файл в разделе Файлы"}`. Pure Java, no third-party HTML library (write a small tolerant tokenizer/tree builder; it must survive broken HTML).
4. Tool `docs_search(query, limit?)` over the sandbox `downloads/` and `docs/` folders (file names + text of .md/.txt/.html/.json/.py/.java/... up to 512 KiB per file, simple tokenised scoring, snippets with the match) so documentation fetched by `download`/`web_fetch` can be searched later. Keep the index lazy and in memory; rebuild on change (mtime).
5. Tests (JVM, loopback servers): every backend parser with recorded sample payloads in `app/src/test/resources/web/**` (hand-written from the providers' documented formats), parallelism (6 slow queries finish in ~ one query time), dedupe, per-query failure isolation, fallback order and cooldown, `web_fetch` on tricky HTML (nested tables, unclosed tags, entities, Cyrillic windows-1251 page, huge page truncation + offset continuation), redirect handling, cancellation. One live smoke test class `WebLiveSmokeTest` that is SKIPPED unless env `JV_LIVE=1`; run it once yourself against the real network (search "погода Гомель", fetch a Russian Wikipedia article and an HTML docs page) and paste the abridged output into docs/WEB_TOOLS.md.
6. `docs/WEB_TOOLS.md`: tool contracts, settings, backend notes with the measured numbers, limits, what is not supported (PDF text).
