# DEVICE CHECKLIST mcpc1 — внешние MCP-серверы (G-01)

Нужен телефон (vivo I2407) с установленной сборкой `app.jarvis.mcpc1` и, для пункта 4, запущенным Telegram-сервером в Termux.
Ничего не отправлять в Telegram без согласия владельца; тестовый аккаунт или «Избранное».

Сборка: `JV_APP_ID=app.jarvis.mcpc1 JV_APK_OUT=$PWD/build/outputs/mcpc1.apk bash build.sh debug`.
Установка и запуск по правилам `docs/AGENT_BRIEF.md` (Wave 2 / Wave 3).

1. Открыть «Настройки» → «Внешние MCP-серверы». Ожидание: пустой список, карточка «Telegram (через Termux)», кнопка «Добавить сервер».
2. Добавить сервер «Тест» с адресом `http://127.0.0.1:9/mcp`, нажать «Проверить подключение». Ожидание: диалог «Не удалось подключиться» с понятным текстом; в списке точка красного цвета и «ошибка: …».
3. Запустить тестовый MCP-сервер по HTTP (например из `tests/mcp` или `python3 -m http.server` не подходит: нужен MCP). Добавить его, «Проверить подключение». Ожидание: «Подключение работает», список имён инструментов; точка зелёная, задержка в мс.
4. Telegram: в Termux `MCP_TRANSPORT=http MCP_PORT=8830 uv run main.py` в каталоге telegram-mcp (с `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `TELEGRAM_SESSION_STRING`). В приложении «Telegram (через Termux)» → «Проверить подключение». Ожидание: список инструментов Telegram (около 100), в журнале запись о проверке.
5. Экран сервера: переключить «Включён» выкл → вкл; у сервера не должно остаться инструментов в агенте, пока выключен (проверить через `agent_tools_list` MCP или по ответу агента «какие инструменты есть»).
6. Экран сервера → «Показ инструментов» → «Через поиск». Ожидание: в списке инструментов агента только `mcp_search` и `mcp_call` (проверить через MCP `agent_prompt_dump`: в системном промпте строка «Внешние MCP-серверы: …»).
7. Голосом или текстом в чате: «найди в telegram инструмент для непрочитанных сообщений». Ожидание: агент вызывает `mcp_search`, затем при необходимости `mcp_call` на читающем инструменте; без вопроса на чтение.
8. Инструмент записи (например отправка сообщения) через чат. Ожидание: диалог «Разрешить действие?» с именем инструмента и именами аргументов (не значениями). «Отмена» → агент сообщает об отказе, сообщение не отправлено. Повторить с «Разрешить» только на тестовом адресате.
9. Убедиться, что в журнале (категория «tools») есть записи `MCP telegram/…` с длительностью и ok, без текста сообщений и без токенов (искать строку сессии в журнале — не должна встречаться).
10. Перезапустить приложение (свайп из «Недавних» и открыть снова). Ожидание: список серверов и инструменты сохранились; точки в состоянии «ожидание» (подключение только по требованию).
11. Остановить Telegram-сервер в Termux, вызвать инструмент из чата. Ожидание: понятный ответ «Соединение с сервером прервалось» или таймаут, без зависания приложения; точка красная.
12. Удалить тестовые серверы («Удалить сервер»). Ожидание: из списка пропали, в «Секретах» нет ключа `mcp.<id>.headers`.
13. Снять скриншоты страницы (светлая и тёмная тема), сравнить с `build/preview/mcpsrv_*.png`: текст строк, точки, отступы.
14. Поворот экрана и системная тема: диалог подтверждения не обрезается.
15. Удалить тестовую сборку: `adb -s $D uninstall app.jarvis.mcpc1`.
