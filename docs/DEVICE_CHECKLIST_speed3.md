# Проверка на телефоне: speed3 (сжатие загрузки, гедж, локальное обращение)

Нужно, когда телефон снова доступен по ADB. Ничего из этого не проверено; всё ниже — не сделано.
Пакет варианта: `app.jarvis.speed3`. Правила фермы: `docs/AGENT_BRIEF.md`, раздел «Side-by-side device builds» и «Wave 3».

## 0. Сборка и установка
1. `export ANDROID_ADB_SERVER_PORT=5038; D=10.61.19.159:38569; adb devices` — должен быть `$D device`.
2. `JV_APP_ID=app.jarvis.speed3 JV_APK_OUT=$PWD/build/outputs/speed3.apk bash build.sh debug`.
3. `adb -s $D install -r build/outputs/speed3.apk`.
4. Открыть «Jarvis [speed3]» через `bash tools/with-screen.sh adb -s $D shell am start -n app.jarvis.speed3/app.jarvis.MainActivity`.

## 1. Настройки (ожидаемо: значения по умолчанию)
1. В журнале приложения при старте голосового режима не должно быть ошибок про `wake.engine`, `stt.format`, `stt.hedgeMs`.
2. Установка модели обращения: в «Обращение и распознавание» нажать установку офлайн-модели (46 МБ). Ожидание: статус «Модель установлена (0.22)».
3. Ключи в настройках `wake.engine` / `stt.format` / `stt.hedgeMs` в UI не выводятся (set1 сделает UI). Проверка через `tools/dev-shot.sh` не нужна; достаточно `adb shell run-as app.jarvis.speed3 cat shared_prefs/*` (только чтение) и поиск ключей.

## 2. Сжатие загрузки (Opus)
1. Включить распознавание «Groq» (ключ должен быть задан). Нажать «проверить» в настройках распознавания.
2. Ожидание: в журнале строка `stt: ogg/opus NN КБ` (одна на сессию), в трассе хода `stt.format = opus`, `stt.bytes_uploaded` ≈ 10–25 КБ для 3–5 с фразы.
3. Тот же ход с `stt.format = wav` (через set1 или `run-as`): `bytes_uploaded` ≈ 150–250 КБ; текст ответа тот же.
4. Записать время «конец речи → текст» у обоих вариантов в `perf_turns` (MCP). Ожидание: Opus короче на сети телефона.

## 3. Гедж STT
1. Установить `stt.hedgeMs = 3000`, цепочку из двух провайдеров, первый — с неверным ключом (ошибка AUTH быстро) — ожидание: второй отвечает сразу, в журнале одна WARN-строка про первого.
2. Первый провайдер с ключом, но при выключенном Wi-Fi/с плохой сетью: ожидание: через ≈ 3 с стартует второй, побеждает первый ответивший с текстом.

## 4. Локальное обращение (P-03)
1. Включить «Режим обращения» при установленной модели. В журнале: «Режим обращения включён», без облачных запросов в простое (`stt.purpose=wake` не появляется для фраз без обращения).
2. Сказать «Джарвис, который час?» (это ты говоришь, не динамик): ожидание — в журнале «Обращение услышано (локально)», затем одна строка облачного распознавания для подтверждения, затем ответ. Замерить задержку «конец фразы → обращение» по TurnTrace `wake_detected`: ожидание ≈ 0,7 с.
3. Сказать несколько фраз без обращения (2–3 минуты обычной речи): в журнале «Речь без обращения (локально …)» или «Локальное срабатывание не подтверждено облаком»; облачных загрузок — только на локальные срабатывания (не больше 10 в минуту).
4. Переключить `wake.engine = cloud`: каждая фраза уходит в облако (ограничение 10/мин), поведение как раньше.
5. Переключить `wake.engine = local`: без подтверждения облаком; ложные срабатывания на обычной речи возможны (см. SPEED.md, раздел 9d).

## 5. Звук и микрофон (запрещено ночью по правилам фермы — выполнять только с владельцем)
1. Реальная речь в микрофон: распознавание, не-срабатывание на телевизор/музыку на громкости разговора.
2. Заметить, есть ли задержка при записи длинной фразы (кодирование Opus на 8 с: лучшее 446 мс, среднее 644 мс по ART — ожидать сопоставимое время на телефоне).

## 6. Уборка
1. `adb -s $D uninstall app.jarvis.speed3`.
2. Отчёт: ожидание — таблица значений из пунктов 2, 3, 4 (задержки и байты) и отметка, что проверено.

## Что сообщить, если что-то не так
* Журнал: строки с тегами STT и WAKE, с `technical`.
* Если Opus не приходит: в журнале строка `stt: ogg/opus … КБ` отсутствует, в трассе формат `wav` — кодер на устройстве откатился в WAV. Причина не выводится в журнал (поле `AudioEncoder.lastError`); её видно только в отладочном прогоне `EncoderCheck`.
