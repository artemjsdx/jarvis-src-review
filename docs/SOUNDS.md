# Сигналы начала и конца записи (Z-01)

10 наборов, у каждого три файла: `<id>_start.ogg` (слушаю), `<id>_stop.ogg` (закончил слушать), `<id>_error.ogg` (ошибка/отмена).
Файлы лежат в `app/assets/sounds/`, список — `sounds.json` (массив, по умолчанию набор `crystal`, выбор владельца).
Всё синтезировано скриптом `tools/gen-sounds.py` (numpy: аддитивный синтез, Karplus-Strong, фильтрованный шум), лицензия «generated (CC0)».
Внешние CC0-источники **не использовались** (не искал: проверяемая лицензия плюс скачивание из этой сети стоили бы больше пользы, чем даёт синтез).
Субъективное качество («приятно ли на слух») **не проверялось**: слушать на стенде нельзя; ниже только измеримые свойства.

## Контракт для разработчика приложения (без Java-кода)

* Загружать через `AssetManager` (`getAssets().openFd("sounds/<id>_start.ogg")`), список наборов читать из `sounds/sounds.json`.
  Поле `durationMs` — длина клипа; Android `MediaCodec` декодирует ровно столько (проверено на ART, см. ниже), ffmpeg добавляет до ~20 мс padding кодека.
* Проигрывать через `SoundPool` (задержка меньше, файлы короткие, предзагружать при старте сервиса) либо `MediaPlayer`;
  `AudioAttributes`: `USAGE_ASSISTANCE_SONIFICATION`, `CONTENT_TYPE_SONIFICATION`. Громкость — системная звукового потока уведомлений/ассистента, свою не поднимать.
* **Start:** сначала играть сигнал, потом открывать микрофон (или открывать микрофон сразу, но выбросить первые ~100 мс записанного звука
  плюс длительность сигнала, если он ещё звучит), чтобы сигнал не попал в запись и не распознался как речь. Самый длинный start — 350 мс;
  при воспроизведении до открытия микрофона достаточно подождать `durationMs` либо `OnLoadComplete`/`OnCompletion`.
* **Stop:** играть после того, как микрофон закрыт (AudioRecord.stop/release), не раньше: иначе сигнал попадёт в хвост записи.
* **Error:** при отмене/ошибке распознавания вместо stop.
* Сигнал не проигрывать, если звук телефона выключен/идёт звонок; настройки «вкл/выкл» отдельно для входа и выхода; по умолчанию включено.
* Формат: OGG Vorbis, 44.1 кГц, моно, ~64 кбит/с, каждый файл 4–6 КБ. Декодер Android поддерживает его с API 1; все 30 файлов декодированы реальным `MediaExtractor`+`MediaCodec` на ART этого телефона:
  `SoundAssetCheck` (`app/src/debug/java/app/jarvis/dev/checks/`), результат «SOUNDCHECK OK», 44100 Гц, моно, длины и пики совпали с таблицей (в `ms` таблицы стоит декодирование ffmpeg).

## Нормировка и измерения

* Громкость клипа: BS.1770 K-взвешивание, **без гейтинга, по всей длине клипа**, цель −20 LUFS; потолок пика −3 dBFS (выбран меньший из двух коэффициентов).
  Встроенный `ebur128` у ffmpeg для клипов короче 400 мс интегральное значение не выдаёт (окно 400 мс), поэтому громкость считает сам скрипт;
  истинный пик ffmpeg для `crystal_start.ogg` показал −7.0 dBFS, совпадает с таблицей.
* Фейды: вход 5 мс (косинус), выход — косинусный спад 30 мс (спад длиннее пяти миллисекунд, чтобы не было щелчка на ещё звучащем хвосте).
* Таблица считается по **декодированным** OGG (`ffmpeg`), то есть после кодека. «Хвост» — максимум абсолютной амплитуды в последних 10…3 мс относительно пика.
* «нот» — число обнаруженных вступлений (по скачкам энергии); «Δвысоты» — полутоны между первой и последней нотой (оценка основного тона по
  самому низкому сильному пику спектра с вычитанием ещё звучащей предыдущей ноты) или, для одиночных глиссандо/шума, между началом и концом активной части;
  «Δцентроида» — сдвиг спектрального центроида между первой и последней четвертью активных кадров.
  Для щипковых (арфа) и ударных центроид закономерно падает у всех звуков, поэтому критерий направления — «Δвысоты».
* Контраст start/stop: `макс. корреляция` — пик нормированной взаимной корреляции волн (1 — одинаковы, около 0 — разные); Слабее всего контраст по высоте у `bowed`
  (+1.0 / −1.9 полутона): start/stop там различаются в основном огибающей (медленно нарастает / резко вступает и затухает), а не высотой.
  У `click` в `error` LUFS −22.1: пик на −3.2 dBFS ограничил усиление.

## Воспроизводимость

`python3 tools/gen-sounds.py` пересоздаёт все 30 файлов и `sounds.json` бит-в-бит (проверено двумя запусками подряд, md5 совпали;
сид шума зависит только от `<id>/<вид>`, ffmpeg вызывается с `bitexact`). `python3 tools/gen-sounds.py --check` декодирует файлы,
печатает таблицу и проверяет: длительность (start 120–350 мс, stop 150–400 мс), размер файла ≤ 25 КБ, суммарно ≤ 600 КБ, пик ≤ −3 dBFS,
что у start высота растёт, а у stop падает. `--check --update-doc` переписывает таблицу выше.

## Что не проверено

* Субъективная приятность и «ненавязчивость» на слух; различимость на динамике телефона — измерена только по сигналу.
* Воспроизведение на устройстве (SoundPool/MediaPlayer): звук на телефоне по правилам стенда не запускался.
* Реальный уровень относительно системных звуков; нужна подстройка громкости в приложении на слух владельцем.
