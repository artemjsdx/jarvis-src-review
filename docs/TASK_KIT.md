## Lead's findings you must account for (layout bugs that look like "cramped / overlapping / cut" UI)
* `Ui.space()` was a bare `View` (fixed to `android.widget.Space`): a bare View with WRAP_CONTENT measures like MATCH_PARENT. Search for other bare `new View(` used as spacers/dividers inside LinearLayouts (`AgentScreen`, `LogScreen`, `Shell` state dot) and make sure they have explicit sizes.
* `LinearLayout` + `gravity=CENTER_VERTICAL` + asymmetric vertical margins shifts the child by `(topMargin - bottomMargin)` (and clips it). `Ui.row` defaults to CENTER_VERTICAL and many call sites use `Ui.lpm(..., bottom)`. Provide a margin-safe helper (e.g. `Ui.rowTop`) or an audit script that greps rows with only top/bottom margins, and fix the call sites you own.
* `Ui.lpm(0, h, ...)` means "width 0 without weight" = invisible; add a lint-style unit test or a helper `Ui.lpwm(weight, margins...)` and replace such uses.
