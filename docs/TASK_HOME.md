## Facts
`ui/screens/HomeScreen.java`: `addQuick(chips, "…")` builds three static chips; a tap calls `j.submit(text, null, "text")` (it IS an agent run, but the texts are fixed, and "Покажи файлы"/"Открой журнал" are caught by `DirectCommands` so the model never sees them). `Jarvis.llmChoices()` gives provider/model/config candidates; `OpenAiClient.chat(config, req, listener, cancel)` streams; `ChatStore.history(conv, maxChars)` gives context; memory: `j.memory.promptSnippet(n)`.

## Deliver
1. `rt/Suggestions.java` (+ pure-Java core `core/agent/SuggestionPrompt.java`): builds a SHORT prompt from: time of day and weekday, the last ~6 user messages across the 3 most recent conversations (titles + first lines, each cut to 120 chars, no tool output), the memory snippet (≤ 400 chars), player state; asks the CURRENT fast model (no tools, `maxTokens` 120, `reasoning=off`, temperature 0.8, `realtime`) for **exactly 3 suggestions as a JSON array of strings, each ≤ 28 characters, Russian, imperative or question, concrete to the context, no duplicates of what the user just did, no emoji**. Robust parsing (accept JSON, fenced JSON, or lines; drop empties/duplicates/over-long; need ≥ 2 valid else fall back).
2. Caching and freshness: cache in `Settings`/file (`suggestions.json`: list + timestamp + context hash); refresh when (a) the home screen is shown and the cache is older than 10 minutes, (b) 8 s after an agent run finishes, (c) the context hash changed. Never block the UI: show the previous chips immediately (or the offline defaults), fade-swap (160 ms) when new ones arrive; a subtle shimmer line only if no chips exist yet. At most one request in flight, cancel on screen hide, never when the app has no key/network, never more than 6 requests per hour (counter in prefs); cost is a few hundred tokens.
3. Offline defaults (used when disabled/no key/failed): context-aware but static: time-of-day greeting variants, "Что нового?", "Включи музыку", "Какие у тебя возможности?" — pick 3 by time of day. They are plain agent messages too.
4. **A tap on a chip sends the text as an ordinary user message to the agent** (`source="text"`), exactly like typing it; it must NOT bypass the agent. If the text happens to match a direct-command pattern that is fine (the agent loop handles it as today), but chips from the LLM are phrased as natural requests, so mostly the model answers. Add a unit test that a chip tap calls `Jarvis.submit` with the chip text and nothing else.
