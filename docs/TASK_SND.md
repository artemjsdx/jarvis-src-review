## Deliver
1. **`audio/Cues.java`** (Android): loads `assets/sounds/sounds.json` + `<id>_start|stop|error.ogg` (10 sets exist, default `crystal`) into a `SoundPool` (attributes `USAGE_ASSISTANCE_SONIFICATION`, `CONTENT_TYPE_SONIFICATION`), lazy init, cheap replay, respects: `cue.enabled` (default true), `cue.set`, separate `cue.start.enabled`/`cue.stop.enabled`/`cue.error.enabled` (default all true), `cue.volume` 0.1–1.0 (default 0.55, relative to the system media/notification volume), do-not-disturb awareness (silent mode → no cue but the visual indicator stays), `cue.custom.start|stop` = a user-picked audio file (copied into the sandbox `cues/`, ≤ 300 KB, ≤ 3 s, validated with `MediaMetadataRetriever`). `preview(id)` plays both of a set (only when the user taps; never automatically). JVM-testable parts (settings resolution, manifest parsing of sounds.json) pure Java.
2. **Integration in `rt/VoiceController`/`MicCapture`**: START cue is played BEFORE the microphone opens (wait for its duration ≤ 350 ms via `SoundPool` completion or a fixed per-asset duration from `sounds.json`), then audio capture drops the first 120 ms so the cue is not recorded/recognised; STOP cue plays AFTER the mic closes in all three end cases (VAD auto-end, manual stop/release, timeout) with a distinct treatment for "nothing heard" (error cue); wake-word detection uses the same start cue when the phrase is recognised and the command capture begins; the cue is skipped for text turns. Never play cues while the TTS is speaking unless it is the start cue for a barge-in. Journal one INFO line per cue decision at DEBUG level.
3. **"I hear you" visual/haptic feedback (Z-02)**: a `ListeningIndicator` model object (level 0..1 RMS from `MicCapture`, state) consumed by the UI (the Home orb already reacts to state: add a `setLevel(float)` entry point on `OrbView` guarded by a TODO-free additive method if `home1` has not changed that file yet; otherwise expose the data through `Jarvis` listener only), plus a short vibration (`VibrationEffect` 18 ms, setting `cue.haptic` default on) on start and a double tick on stop. Edge glow around the screen is the glass/kit agents' job: just publish `levelFlow` + state in one place (`VoiceControl` listener extension, additive).
4. **Microphone yielding (Z-03)**: `audio/MicArbiter.java`: registers `AudioManager.registerAudioRecordingCallback` (API 24+) and, on API 29+, uses `AudioRecordingConfiguration.isClientSilenced()`; logic: when ANOTHER app's recording becomes active (active configs minus our own capture sessions; anonymised configs still count) OR our own capture is silenced by the system, pause our capture and the wake listener within 300 ms, show state "Микрофон занят другим приложением" (journal INFO + `VoiceControl` state), and automatically resume 1.2 s after the other recording ends (debounced; max 3 resume attempts, then notify). While a phone call is active (`TelephonyManager`/`AudioManager.MODE_IN_CALL|IN_COMMUNICATION`) also stay silent. Unit-test the pure state machine (events: others-start/stop, silenced, call, user-toggle) with a table; the Android glue is thin. Replace the confusing journal text about "system does not give microphone audio in the background" with the arbiter's clear states (coordinate: `log1` owns the journal screen, you only change the strings in `VoiceController`/`MicCapture`/`WakeController`).
5. **Speech speed (Z-04)** wiring in `core/voice` providers (settings key `tts.speed` 0.7–1.4, default 1.0): ElevenLabs `speed` voice setting (0.7–1.2 → clamp), Edge `prosody rate` (`+N%`/`-N%`), gTTS `slow` only for < 0.9, Silero/F5/OpenRouter: ignore (document). `SpeechService` includes speed in the cache key. Expose `TtsCapabilities.supportsSpeed(providerId)` for the UI (`set1` wires the slider).
6. **Sound packs from the internet (optional, behind a button)**: `audio/CuePacks.java` downloads a pack zip from a list of VERIFIED CC0 sources and installs the files as extra sets (`filesDir/cues/<pack>/`): research and verify 2–3 direct-download CC0 UI-sound packs reachable from this network (e.g. Kenney "UI Audio"/"Interface Sounds" on kenney.nl or their GitHub mirrors, OpenGameArt CC0 packs) — record URL, licence text URL, size, sha256 in `docs/SOUNDS.md`; use the existing `Downloader` + `ZipSafe`; convert nothing on the device: only `.ogg`/`.wav`/`.mp3` files up to 300 KB are accepted as cues. If no source can be verified, ship only the custom-file option and say so.
7. Settings keys documented in `docs/SND_SETTINGS.md` (key, type, default, Russian label, help) for `set1` to expose. Add a debug scene preview if you create any UI (none required).
