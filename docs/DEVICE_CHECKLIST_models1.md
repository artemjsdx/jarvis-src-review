# Проверка на устройстве: models1 (S-05, S-06, S-07, X-02)

Статус на момент сборки: телефон недоступен по ADB (режим поездки владельца). Ниже — что нужно сделать на vivo I2407.
Сборка: `JV_APP_ID=app.jarvis.models1`, приложение «Jarvis [models1]». Перед проверкой: `export ANDROID_ADB_SERVER_PORT=5038; D=10.61.19.159:38569`.

## A. Установка и данные
1. Установить `build/outputs/models1.apk` (`adb -s $D install -r ...`). Открыть «Jarvis [models1]».
2. Ожидаемо: при первом открытии журнал пуст по LLM; в «Настройки → Языковая модель» видны блоки «Провайдер», «Модель», «Недавние», «Генерация», «Запасные провайдеры».

## B. Провайдер (компактная строка)
3. Нажать строку провайдера. Ожидаемо: шторка «Провайдеры», поиск, у каждого провайдера бейдж «ключ задан» / «ключа нет» / «ключ не нужен», текущий отмечен.
4. Ввести в поиске «deep». Ожидаемо: остаётся DeepSeek.
5. Выбрать DeepSeek без ключа. Ожидаемо: если у текущей модели OpenRouter есть история в чате — вопрос о смене (см. раздел E); иначе тихо, тост «Модель: …».

## C. Список моделей и журнал
6. OpenRouter с ключом: «Выбрать модель» → список. Ожидаемо: строка статуса «Моделей: 456 · обновлено только что», у строк чипы «контекст 1,0 млн», «вывод …», «инструменты», «рассуждение», «изображения», строка «Цена: $0,09 вход · $0,18 выход за 1 млн токенов».
7. Фильтры «С инструментами», «С рассуждением», «Бесплатные» появляются, потому что данные есть; фильтр «Бесплатные» даёт `:free`-модели.
8. Провайдер без ключа (например, DeepSeek без ключа) → «Обновить список». Ожидаемо: статус «Ошибка загрузки: Нужен API-ключ…», в журнале (вкладка Журнал, категория llm) строка ERROR с текстом «Не удалось загрузить список моделей (deepseek)».
9. Неверный ключ OpenRouter (например, испорченный) → «Обновить список». Ожидаемо: в журнале ERROR с «[HTTP 401]» и техническим «HTTP 401 …» в подробностях; статус в карточке показывает HTTP-код.
10. Выключить сеть → «Обновить список». Ожидаемо: строка ошибки с сетевым текстом; повтор автоматически не запускается раньше 10 минут (проверить журналом).

## D. Недавние
11. После нескольких смен моделей строка «Недавние» показывает плитки «модель / провайдер» (до 8), текущая подсвечена. Нажатие переключает модель (с проверкой из раздела E).

## E. Смена модели (X-02)
12. Модель без инструментов в чате с командами (например, модель «без инструментов» из каталога) при переписке с вызовами инструментов: ожидаемо вопрос «Сменить модель на «…»?» с причиной «У модели нет инструментов…».
13. Длинная переписка (> окна новой модели, для проверки подходит модель с маленьким окном, например 8 000 токенов): ожидаемо причина «Переписка ≈ … токенов, а окно … —». Кнопка «Переключить и обрезать старое» → тост, в чате старое не попадает в запрос.
14. Та же ситуация → «Передать краткое резюме»: появляется шторка «Резюме переписки», через несколько секунд в чате разделитель «— контекст очищен —» и системный элемент «Резюме предыдущего контекста: …» (≤ 1500 знаков). Следующий вопрос в чате получает ответ с учётом резюме.
15. «Отмена» ничего не меняет.
16. Выбрать realtime / audio / tts модель (например, «gpt-4o-realtime-preview», если она есть в каталоге): ожидаемо диалог «Не для текстового чата», модель не выбирается.
17. В чате (главный экран, кнопка модели) выбрать модель: то же поведение, что в настройках.

## F. Параметры
18. Уровень рассуждений: для DeepSeek `deepseek-flash` доступны «Низкий», «Высокий», «Максимум»; «Средний» выключен с пояснением «Модель не поддерживает этот уровень». Нажатие на выключенный — тост.
19. Для модели без рассуждений (например, `deepseek/deepseek-chat` в OpenRouter) уровни кроме «Выкл» выключены; «Авто» доступен.
20. Температура: у модели с `temperature=NO` — надпись «Модель не принимает температуру», ползунка нет. У модели с неизвестным статусом — пояснение с журналом.
21. Максимум токенов: ввести 999999 → тост «Ограничено лимитом модели: 943 тыс.» (для OpenRouter DeepSeek v4 flash), в поле значение лимита.
22. Контекст: переключатель «Авто» → подпись «Авто: N тыс. символов · окно модели …». Выключить → ползунок, подпись «Вручную · окно модели …».
23. Шаги агента: переключатель «Без ограничения» → подпись «без ограничения (не больше 200)». Запрос агента → в журнале строка «Шаги агента без ограничения: жёсткий предел 200».
24. Отказ параметра: при первом запросе к модели, которая отвергает параметр (например, температуру), журнал: WARN «Провайдер отклонил параметр, повтор без него», затем «параметр temperature не поддерживается моделью …: больше не отправляю». Второй запрос — без повторной ошибки. После перезапуска приложения строка не повторяется.

## G. Тема и визуал
25. Светлая тема (Настройки → Тема → светлая): карточки модели, чипы и плитки «Недавние» читаемы, контраст текста ≥ норм.
26. «?» у каждого заголовка открывает понятный текст. Окно закрывается по кнопке.
27. Проверить на узком экране: чипы переносятся по строкам, цена не обрезается.

## H. Регресс
28. Вкладка «Журнал»: новые строки llm не засоряют журнал при обычном чате (нет повторных WARN/ERROR без причины).
29. Чат и голос работают с выбранной моделью (короткий запрос «Который час»).
30. Резервный провайдер (Запасные провайдеры) по-прежнему используется при сбое основного.

Деинсталляция после проверки: `adb -s $D uninstall app.jarvis.models1`.

## I. API-ключ (S-01..S-03)
31. Открыть провайдера OpenRouter без ключа. Ожидаемо: блок «API-ключ», строка «ключ не задан», пояснение «Хранится только на этом устройстве…» (с Keystore или «без шифрования», в зависимости от телефона).
32. Вставить ключ (поле или кнопка-скрепка), нажать «Сохранить». Ожидаемо: тост «Ключ сохранён», поле очищается, фокус уходит с поля, строка «сохранён: ••••XXXX · ДД.ММ ЧЧ:ММ».
33. Нажать глаз: иконка меняется (перечёркнутый глаз), текст в поле виден; повторно — скрыт. Переход плавный (около 120 мс).
34. «Сохранить» и «Удалить» одинаковой ширины, зазор заметен (около 12 dp), не слипаются.
35. «Проверить ключ» с верным ключом: спиннер «Проверяю ключ…», затем «ключ принят» и «ответ за N мс · GET /key». В журнале (вкладка Журнал, llm) строка INFO «Проверка ключа (openrouter): ключ принят».
36. «Проверить ключ» с неверным ключом (например, испорченным): пилюля «неверный ключ», текст «Неверный, просроченный или отозванный API-ключ», «Подробности» показывает HTTP 401. В журнале одна строка WARN с «[HTTP 401]».
37. Без сети: «Проверить ключ» → пилюля «нет сети», текст про соединение. Одна строка WARN в журнале.
38. «Удалить» → тост «Ключ удалён», строка «ключ не задан», провайдер в шторке показывает «ключа нет».
39. Нажать «?» у заголовка «API-ключ»: шторка с четырьмя короткими пояснениями, кнопка «Понятно» закрывает её.
40. В журнале и в настройках ключ не виден целиком ни в одном месте (проверить поиск по журналу строкой ключа).
