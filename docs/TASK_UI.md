# TASK UI — native screens (shared brief; your screen list is in the spawn message)

Read first: `docs/AGENT_BRIEF.md` (rules + tooling), `NOTES.md`. Product: Jarvis — a voice-first assistant with a real agent runtime.

## Design language (already implemented — USE it, do not reinvent)
`app/src/main/java/app/jarvis/ui/`: `Ui` (tokens: `Ui.P` palette, `Ui.dp`, `Ui.text(ctx,text,kind[,color])`, `Ui.button(...)`, `Ui.iconButton`, `Ui.chip`, `Ui.glass(r)`, `Ui.row/column/lp/lpm/space/divider`, `Ui.pressScale`, `Ui.ms(base)` for animation durations that honour reduced motion), `GlassDrawable`, `Backdrop`, `OrbView` (animated Jarvis mark with `setMode(OrbView.Mode)` and `setLevel(0..1)`), `OverlayHost` (all in-app windows), `Dialogs` (confirm/info/prompt/choose/sheet/progress), `Widgets` (card, sectionTitle, row, pill, Toggle, segmented, Slider, field/fieldBox, Spinner, empty, Progress, pageHeader), `Shell` (header + dock + screens), `Host`/`Screen` (screen contract: build(), title(), onShow(arg), onHide(), onBack(), onActivityResult, onInsets). Icons: `R.drawable.ic_*` (Lucide, ~105: mic, mic_off, send, paperclip, stop, play, pause, skip_next, skip_prev, music, folder, folder_open, file, file_text, file_audio, terminal, settings, sliders, log, voice, home, chat, bot, plus, close, chevron_*, check, copy, trash, download, upload, refresh, wifi, wifi_off, battery, key, globe, shield, info, warning, alert, more, search, edit, save, eye, eye_off, share, volume, volume_off, headphones, sparkles, zap, clock, history, link, drive, layers, cpu, activity, brain, ok, fail, loader, heart, star, moon, sun, palette, language, ear, radio, waves, phone, plug, usb, package, archive, wrench, list, arrow_up, arrow_down, external, lock, bell, folder_plus, file_plus, rotate, cloud, server, timer, gauge, bug, code, image, video, wand, flask, bolt). If you truly need another icon run `python3 tools/gen-icons.py` after adding its Lucide name to the `ICONS` dict (name must exist in lucide repo `icons/<name>.svg`).

Style rules (from the product owner — they are acceptance criteria):
* Black/white base with white-violet / lavender accents, "liquid glass": translucent surfaces **with clearly visible borders**, depth. No cyberpunk, no neon overload, **no emoji anywhere**, no system dialogs/toasts/switches/seekbars, no blue ripples (all pressed feedback is lavender via `Ui.rippleOn`/`Ui.pressScale`).
* **Compact, working layout**: no giant headings, no endless big buttons. Titles ≤ 20sp, body 15sp, captions 12sp. Rows ~48–56dp. Never spend half the screen on chrome.
* Every window is custom (OverlayHost/Dialogs) with a clear close affordance and enter/exit animation. Only Android permission prompts and the system file picker are system windows.
* Animations: expressive but cheap (property animations, no per-frame allocations, no blur). Respect `Ui.reduceMotion` (use `Ui.ms()`; skip motion when `Ui.reduceMotion`). Hidden screens must not animate (stop things in `onHide`).
* Weak phone (3 GB RAM): lists use `ListView` + `BaseAdapter` with view recycling (no thousand-view LinearLayouts); no bitmaps decoded at full size; no work on the UI thread (disk, network, DB queries > few ms go to a background thread and results are posted back with `j.main.post`).
* All user-visible text in Russian, short and concrete. Errors: human sentence first, technical detail available behind a "Подробности" affordance.
* Never fake data in product code. Empty states say what to do. Buttons that cannot work yet must not exist.
* Honest status: show real state from `Jarvis` (see below), not decoration.

## Runtime API you code against (`app.jarvis.rt.Jarvis j = host.jarvis()`)
* State/events: `j.addListener(JarvisListener)` / `removeListener` (register in `onShow`, remove in `onHide`; callbacks are on the main thread): `onState(AState,detail)`, `onChat(ChatEvent{type ADDED/UPDATED/STREAM/STREAM_END/CLEARED/SWITCHED,item,streamText,runId})`, `onLevel(float)`, `onMusic(MusicOut.Info)`, `onToast`, `onNavigate`, `onRunChanged(boolean)`, `onPermissionNeeded`, `onPermissionResult`, `onLastAction(text,ok)`, `onProvidersChanged()`. `j.state()`, `j.stateDetail()`, `j.lastActionText()/lastActionOk()`, `j.isBusy()`.
* Commands: `j.submit(text, attachments|null, "text"|"voice")`, `j.cancelAll()`, `j.voice` (`VoiceControl`: startListening/stopListening/cancel/setWakeEnabled/isWakeEnabled/isMicActive/micProblem), `j.speaker` (`Speaker`: speak/stop/isSpeaking), `j.music` (`MusicOut`, may be null until the module is attached), `j.attach(Uri, progress)` (streams a picked document into inbox/, off the UI thread!).
* Data: `j.settings` (`Settings`: get/getBool/getInt/getFloat/getList/set/setBool/remove, key constants), `j.secrets` (`Secrets`: get/set/has/remove/names/importJson, `Secrets.mask`), `j.chat` (`ChatStore`: currentConversation, newConversation, conversations, items(conv,beforeSeq,limit), add/update, deleteConversation, history), `j.journal` (`SqlJournal`: query/export/clear/count/addLiveListener), `j.sandbox` (`Sandbox` directories `root, work, inbox, downloads, music, docs, tmp, bin`; `resolve(String)`, `rel(File)`), `j.shell` (`ShellSession`: `run(command, cwdArg, timeoutMs, CancelToken, Sink)`, `cwd()`, `history()`), `j.memory` (`MemoryStore`: all/put/delete/clear/search), `j.tools` (`ToolRegistry`: specs()/names()/get(name) — descriptions are what the model sees), `j.llm` (`OpenAiClient`: `listModels(cfg, cancel)` — blocking, call off the UI thread), `j.llmChoices()` / `j.choiceFor(providerId, model)` / `j.providerId()` / `j.modelFor(id)` / `j.setModel(id, model)`, presets: `app.jarvis.core.llm.Presets.all()/get(id)` (`ProviderPreset`: id, name, baseUrl, note, verified, modelHints, keyRequired). Keys live in `j.secrets` under `"key."+providerId`. `ChatItem` (`app.jarvis.data.ChatItem`) is the chat row model (kinds USER, ASSISTANT, TOOL, ERROR, SYSTEM; tool cards have `toolName, toolArgs, summary, ok, durationMs, toolStatus`).
* `Host` (what the activity offers): `navigate("settings/llm")`, `overlays()`, `pickDocument(this, requestCode, mimeTypes, multiple)` + `onActivityResult`, `requestPermission`, `hasPermission`, `copyToClipboard`, `shareFile`, `openUrl`, `openBatterySettings`, `hideKeyboard`, insets via `onInsets(top,bottom)` (bottom already includes the dock).
* Audio/voice modules are being written by other agents in parallel; when a feature depends on a module that is not attached yet (`j.music == null`, `j.voice == VoiceControl.NONE`), show an honest disabled state, never crash.

## Preview workflow (REQUIRED — you must look at your screens)
1. Write scenes in `app/src/debug/java/app/jarvis/dev/scenes/<YourName>Scenes.java` (public final class with `public static void render() throws Exception`). Use `PreviewKit.shell("agent")` to get the REAL `Shell` with your screen inside (real `Jarvis` runtime with SQLite/sandbox in a temp dir), `PreviewKit.seedChat()`, and `PreviewHost.render(view, "name")`; use `PreviewHost.pump(ms)` to let posted work/animations run before rendering; create extra data through the real stores/tools (e.g. write files into `j.sandbox`, add `ChatItem`s via `j.chat`, log lines via `j.journal`).
2. `export JV_PREVIEW_OUT=build/preview-<yourname>; bash tools/preview.sh <YourName>Scenes` (≈1 min) → PNGs in that folder → open them with your image-reading tool and critique them like a designer: alignment, spacing, contrast, truncation, empty/long-content/error states, 3 GB-phone density. Iterate until it looks like a polished product. Render overlays/dialogs too (e.g. call `Dialogs.*`, `PreviewHost.pump(300)`, then render the shell).
3. Preview runs on the phone's real Android runtime, so crashes/ANR-class bugs (NPE, resource errors, layout exceptions) show up there. Fix every `SCENE FAILED`. Use `export JV_EXCLUDE=...` (egrep of source paths) only if another worker's half-written file blocks the build, e.g. `JV_EXCLUDE='core/audio/|core/adb/'`.
4. Builds are independent per invocation (`bash build.sh debug`), so parallel workers do not collide; but sources are shared — touch only the files you own.

## Ownership rule
Each agent owns only the files named in its spawn message. Shared files (`ui/Ui.java`, `Widgets.java`, `Dialogs.java`, `Shell.java`, `Host.java`, `Jarvis.java`, `AndroidManifest.xml.in`, resources): if you need an addition, put your own helper in a new file inside your package (e.g. `ui/chat/`, `ui/files/`, `ui/settings/`) and mention it in the final report. Tiny, clearly additive fixes to `Widgets`/`Dialogs`/`Ui` are allowed (e.g. a missing option) — keep signatures backward compatible, rebuild everything afterwards, and list them in your report. New drawables go to `app/res/drawable/` with your own prefix (`u1_…`, `u2_…`), strings are inline Russian (no strings.xml needed).

## Done when
`bash build.sh debug` is clean; all your scenes render without `SCENE FAILED`; you looked at every PNG and fixed visual problems; interactive logic was exercised in preview via real calls where possible (e.g. add items → list shows them; run a real shell command through `j.shell` and show output; export the journal to a file and check it exists). Final report ≤ 40 lines: files, what works, what you could only check visually, known gaps.
